# 新手帮助

> 直接结论：第一次配置要拿到一条能验证、能回退、能说清失败原因的连接。本站当前没有通过五项标准的免费资源，本文只给判断与操作方法，不替你担保任何服务的可用性。先学会核验来源、条款与连接状态，再决定要不要注册。

## 直接结论与适用边界

第一次配置需要三样东西同时到位：来源可核对的客户端、来源与条款能说清的订阅、一套你重复得出来的验证方法。缺任何一样，后面都会变成反复换节点、反复重装、反复注册。

本站当前收录的合格免费资源为 0 条，审核日期 2026-10-24，下次复核 2026-11-07。这个数字的意思是，没有资源同时通过来源可追溯、额度与有效期及设备数和条款可同时核对、不索取不可撤销的权限、两个独立时点可复核、允许引用结论五项标准。它不表示全网没有免费服务，也不表示免费方案一定不能用。你可以用第 13 节的方法自己核验，核验不过就停在原地，不必因为“限时”“最后一天”之类的字样去注册。

免费的成本通常落在三个地方：你的时间、你的账号、你的流量数据。时间花在安装、排障、重新找订阅；账号花在注册、验证、绑定手机号；流量数据则是运营商、服务方与出口三段都能看到的元数据。把这三项写进预算，再谈免费是否划算。

适用边界有四条：

- 你有一台自己能改网络设置的设备。公司或学校统一管理的设备不在本文范围内。
- 你接受先验证再使用，不把任何未核验的订阅导入主力设备。
- 你愿意为止损设定条件，例如连续两次严重故障就停用。
- 你不打算用代理隐藏违法行为，也不指望代理带来匿名。

上面任意一条不成立，先把第 9 节与第 14 节读完，再回到配置步骤。配置本身不难，难的是知道什么时候该停。

## 概念与实体关系

这类工具由一组角色组成，每个角色只负责一段。把角色认清，界面上的词就能对上号，出问题时也知道该看哪里。

| 实体 | 它是什么 | 你通常在哪里看到 |
| --- | --- | --- |
| 应用 | 浏览器、聊天软件、终端命令，发起连接的一方 | 任务管理器、浏览器地址栏 |
| 系统代理设置 | 操作系统提供的代理开关，告诉支持它的应用把请求交给谁 | 系统设置中的代理页 |
| 客户端界面 | 图形外壳，负责导入订阅、选择节点、显示状态 | 应用窗口与托盘图标 |
| 内核 | 真正建立隧道、匹配规则、转发流量的程序 | 进程列表、日志文件 |
| 配置文件 | 内核读取的规则、DNS 与入站出站定义 | 客户端的配置目录 |
| 订阅 | 一个地址，返回节点清单与部分配置 | 客户端的订阅管理页 |
| 节点 | 一台可连接的服务器入口，含地址、端口、协议与凭据 | 节点列表 |
| 协议 | 客户端与节点之间的封装与认证方式 | 节点详情 |
| 服务方 | 提供节点与订阅的运营者，口语里叫机场 | 订阅域名与账单 |
| 出口 IP | 目标站点看到的来源地址 | IP 查询页 |
| DNS 解析器 | 把域名换成 IP 的服务 | 客户端 DNS 设置、系统设置 |
| TUN 虚拟网卡 | 接管系统三层流量的虚拟设备 | 网络适配器列表 |
| CA 证书 | 验证 TLS 服务器身份的信任锚 | 系统证书管理 |

这些实体之间的关系是固定的，服务商换名字也改不了它们的分工。

| 实体 A | 关系 | 实体 B | 说明 |
| --- | --- | --- | --- |
| 应用 | 交给 | 系统代理或 TUN | 决定谁接管流量 |
| 客户端界面 | 管理 | 内核 | 界面只是外壳，关掉窗口内核可能还在运行 |
| 内核 | 读取 | 配置文件 | 配置错误通常在启动时暴露 |
| 订阅 | 生成 | 节点清单 | 更新会覆盖清单里的旧节点 |
| 节点 | 使用 | 协议与传输 | 同一地址可以配置不同组合 |
| 内核 | 查询 | DNS 解析器 | 解析位置决定是否泄漏 |
| 出口 IP | 访问 | 目标站点 | 目标站点只看到出口地址 |
| 服务方 | 运营 | 节点与订阅 | 条款与日志政策由它决定 |

```text
应用（浏览器 / 聊天 / 终端）
   │ 发起连接
   ▼
系统代理设置 ──► 客户端界面 ──► 内核
                                  │
            订阅 ── 返回清单 ─────┤
                                  │
                     节点 = 地址 + 端口 + 协议 + 凭据
                                  │
                          加密隧道（TLS / QUIC）
                                  │
                              出口 IP ──► 目标站点
                                  │
                          DNS 解析器 ◄┘
```

几个最容易被混淆的区别：

先看客户端与内核。界面打不开时，可能是内核已经退出，也可能是界面本身崩溃。反过来，关闭窗口后内核仍在后台运行，系统代理没有撤掉，就会出现“明明关了软件却上不了国内网站”的错觉。遇到这类情况，先看进程，再看系统代理开关。

订阅和节点也常被当成同义词。订阅是清单，节点是清单里的一行。订阅地址失效，已经导入的节点通常还能用到下一次更新；订阅更新成功，节点数量也会因为服务方调整而增减。把订阅当成节点，就会在更新后误以为换了一整批服务器。

节点的入口位置与线路走向要分开看。节点是入口地址，线路是入口到出口经过的路径。同一个节点在不同时段表现不同，常见原因在路径拥塞，节点本身未必有故障。

机场属于服务形态，协议属于技术方案。同一家服务可以用多种协议，同一种协议也可以被很多服务使用。选服务时看条款与线路，选客户端时才看协议支持。

配置与订阅的关系稍复杂。订阅更新一般只覆盖它自己下发的那一段，你手写的规则与 DNS 设置能否保留，取决于客户端如何合并配置。备份时两样都要导，只备份订阅链接会在换客户端后丢掉本地规则。

## 按平台完成最小配置

最小配置指一个客户端、一份订阅、一个接管模式加一次验证。目标是一条路径能通，其余功能按需再加。以下步骤只写通用位置，不同版本的菜单名称会有差异，找不到时优先看客户端的设置分类与官方文档，不要照着来路不明的图文教程点。

五个平台共用的顺序：

1. 定来源。只从项目官方发布页下载，记录版本号与文件名，能核对校验和就核对。
2. 安装。记下安装位置、是否开机自启、是否需要额外运行时。
3. 导入。优先用订阅链接，失败再试本地配置文件；导入后确认节点数量与更新时间。
4. 选模式。先用系统代理或规则模式，确认一个目标网页能打开。
5. 验证并记录。出口 IP、DNS 结果、延迟与失败现象都写进记录，后面排障要用。

每一步都有完成标志，对不上就先停下。

| 步骤 | 完成标志 | 常见失败 |
| --- | --- | --- |
| 下载 | 文件名与发布页一致，能查到版本 | 网盘改名、捆绑安装器 |
| 安装 | 应用能启动，版本号可见 | 缺运行时、被安全软件拦截 |
| 导入 | 节点数与更新时间显示正常 | 链接过期、格式不兼容 |
| 接管 | 系统代理开关或虚拟网卡生效 | 权限不足、端口冲突 |
| 验证 | 出口 IP 与所选地区一致 | 规则未命中、DNS 泄漏 |

平台与常见开源客户端的对应关系如下，具体下载地址以各项目官方发布页为准。

| 平台 | 常见开源客户端 | 备注 |
| --- | --- | --- |
| Windows | Clash Verge Rev、v2rayN | 发布页会注明运行时与依赖要求 |
| macOS | Clash Verge Rev、Hiddify | 需要批准系统扩展 |
| Android | v2rayNG、FlClash、Hiddify | 从发布页或可信应用仓库获取 |
| iOS | 以 App Store 可获取的客户端为准 | 多数需要付费或特定地区账号 |
| Linux | sing-box、Mihomo 内核 | 命令行配置，用 systemd 管理 |

### Windows

从官方发布页取得安装包或压缩包。部分客户端依赖 WebView2 或 .NET 桌面运行时，发布页会写明要求，缺依赖时表现为双击无反应或启动后白屏。首次运行若弹出防火墙提示，允许专用网络即可，公用网络的放行要谨慎。

系统代理开关位于设置中的网络与 Internet 代理页。客户端通常会自动改写这里，退出时未必自动恢复，所以配置前先截图记录原始状态。TUN 模式需要管理员权限，并且会安装虚拟网卡驱动，公司电脑可能禁止安装驱动。

验证顺序：先看托盘图标状态，再看系统代理地址是否指向本机端口，最后用浏览器打开一个目标站点。三项都对仍打不开，进入第 10 节。

### macOS

安装包多为 dmg，拖入应用程序目录即可。首次打开会被系统拦截，需要在隐私与安全性里允许。使用 TUN 或网络扩展时，系统会要求批准扩展，批准后可能提示重启客户端。

系统代理位于网络设置的详细信息代理页，可分别设置网页代理与安全网页代理。TUN 模式会创建 utun 接口，退出客户端后应在网络接口列表中消失。若代理开关残留，手动关闭一次。

macOS 的安全软件与公司管理配置可能限制扩展加载，表现为批准后仍然不生效。这时先用系统代理模式，不要反复重装。

### Android

安装包从项目发布页或可信应用仓库获取，安装时系统会要求允许安装未知来源应用。首次连接会弹出 VPN 连接请求，这个授权对应系统级流量接管，授予后其他 VPN 类应用通常无法同时生效。

导入订阅后先关闭分应用代理，确认全局可用，再逐项添加需要走代理的应用。省电策略会杀掉后台长连接，需要把客户端加入不受限制名单。切换 Wi-Fi 与移动网络时可能短暂断流，属正常重连。

### iOS

客户端依赖 App Store 的地区与账号，部分客户端只在特定地区上架，也有付费客户端。安装后同样需要允许 VPN 配置，系统会在状态栏显示 VPN 标记。iOS 不允许普通应用直接改系统代理，流量接管由客户端写入的 VPN 配置完成。

按需连接功能会在特定网络下自动开启，配置不当会出现“连上却上不了网”。先关闭按需连接做一次手动验证，再决定是否启用。来源不明的描述文件不要安装，它会扩大信任范围。

### Linux

命令行内核适合网关与服务器环境。配置文件放在用户配置目录，用 systemd 管理进程，日志通过 journalctl 查看。TUN 需要 CAP_NET_ADMIN 或 root，长期运行建议用能力位，避免全程 root。

DNS 处理容易出问题。systemd-resolved 默认在 127.0.0.53 监听，内核若直接改 etc/resolv.conf 可能被覆盖。要么让内核接管 DNS，要么把系统解析器指向内核提供的地址，两者只选一种。

验证：查看服务状态、监听端口、出口 IP 三项。改动前备份配置文件，回滚时直接换回旧文件并重启服务。

### 权限与限制对照

五个平台要的授权不一样，拒绝授权后损失的功能也不一样。先看清代价，再决定给不给。

| 平台 | 需要的授权 | 拒绝后的功能损失 | 是否可撤销 |
| --- | --- | --- | --- |
| Windows | 管理员权限、虚拟网卡驱动、防火墙放行 | 只能用系统代理，覆盖不完整 | 可以，退出并卸载驱动 |
| macOS | 系统扩展批准、管理员权限 | 无法使用 TUN，只能用系统代理 | 可以，在隐私与安全性中移除 |
| Android | VPN 连接授权、后台运行白名单 | 无法接管流量，或频繁断线 | 可以，断开连接即撤销 |
| iOS | VPN 配置授权、按需连接 | 无法接管流量 | 可以，删除配置即撤销 |
| Linux | CAP_NET_ADMIN 或 root、服务安装 | 无法创建 TUN，只能用本地端口 | 可以，移除能力位与服务 |

授权原则是最小够用。能用系统代理验证链路，就先不要申请管理员权限；能用分应用代理，就不要让全部应用走隧道。权限给得越多，卸载时的残留与冲突也越多。

### 验收与回退

配置完成后按这张表验收，六项都过再导入日常使用。

| 检查项 | 通过标准 | 不通过先看 |
| --- | --- | --- |
| 客户端进程 | 进程存在，CPU 不持续占满 | 依赖、权限、配置语法 |
| 本地入口 | 本机端口处于监听状态 | 端口冲突、配置未加载 |
| 订阅 | 节点数与更新时间可见 | 链接、UA、网络连通 |
| 代理链路 | 节点延迟测试有结果 | 地址、端口、防火墙 |
| 出站 | 出口 IP 与节点地区一致 | 规则、DNS、泄漏 |
| 回退 | 关闭后能恢复直连 | 系统代理残留、TUN 路由 |

回退准备在配置前做完，成本最低：

- 记录原始系统代理设置，最好截图。
- 导出当前配置与订阅链接，放在加密盘或密码管理器里。
- 记下客户端与内核版本号，方便回滚。
- 知道如何强制退出内核进程，而不只是关闭窗口。
- 留一条不依赖代理的备用通道，例如手机热点。

## 系统代理与 TUN

两种接管方式的主要差别在覆盖范围与权限，速度通常不是决定因素。

| 维度 | 系统代理 | TUN |
| --- | --- | --- |
| 覆盖范围 | 只覆盖读取系统代理设置的应用 | 接管网络层流量，可按规则分流 |
| DNS 处理 | 多数情况仍走系统解析器 | 可由内核接管，减少泄漏 |
| 所需权限 | 普通用户 | 管理员、系统扩展或 VPN 授权 |
| 典型故障 | 浏览器可用，其他应用不走 | 开启后完全没网、路由冲突 |
| 回退方式 | 关闭开关即恢复 | 退出客户端并确认虚拟网卡消失 |
| 适用场景 | 桌面端起步、临时使用 | 需要覆盖全部应用或分应用精细控制 |

系统代理是应用层约定。程序读取系统设置才会遵守，不读的程序照常直连。浏览器、部分下载工具会读，Java 应用、部分游戏、容器与终端工具经常不读，这就是“只有浏览器能上网”的来源。

TUN 在网络层接管，创建虚拟网卡并修改路由表，所以需要更高权限。它能覆盖不读代理设置的程序，也会和其他 VPN、虚拟机网卡、企业安全软件争夺路由。手机上授予的 VPN 权限本质接近 TUN，因此同一时间通常只有一个代理应用生效。

选择顺序：先用系统代理确认订阅与节点可用，再决定是否升级到 TUN。不要为了彻底而一上来就开 TUN，权限越大，排障面越宽。

TUN 出问题时按三步回退：退出客户端，检查虚拟网卡是否消失，检查默认路由是否恢复。路由残留会导致断网，重启网络服务或重启系统可以清理。

## DNS 与分流

DNS 决定你把域名交给谁解析，分流决定哪些流量走隧道。两者配错的表现很相似，都是“能连上但打不开”或“部分网站很慢”。

三种解析路径：

- 本地解析。应用向系统解析器查询，再由运营商 DNS 递归。速度快，请求对本地网络可见，可能被污染。
- 远端解析。客户端把域名交给出口服务器解析，本地只看到加密流量。减少污染，但出口看到的域名更集中。
- 加密解析。使用 DoH 或 DoT，把查询放进 TLS 连接。能减少明文观察，仍要信任解析服务方。

分流规则按类型匹配，顺序从上到下，命中第一条就停止。

| 规则类型 | 匹配对象 | 适用场景 | 注意 |
| --- | --- | --- | --- |
| DOMAIN | 完整域名 | 单个站点强制直连或代理 | 数量多时维护成本高 |
| DOMAIN-SUFFIX | 域名后缀 | 整个站点及其子域 | 后缀写太短会误伤 |
| DOMAIN-KEYWORD | 域名中的关键词 | 临时兜底 | 最容易误伤，尽量少用 |
| IP-CIDR | IPv4 网段 | 已知地址段 | 需配合 no-resolve 避免提前解析 |
| IP-CIDR6 | IPv6 网段 | 双栈环境 | 容易与 IPv6 泄漏混淆 |
| GEOIP | 国家或地区代码 | 按地区粗分 | 数据库有时效，结果会变 |
| PROCESS-NAME | 进程名 | 桌面端分应用 | 各平台支持程度不同 |
| MATCH | 全部剩余流量 | 兜底 | 必须放最后 |

四条实践规则：

精确规则放前面，兜底放最后。把 MATCH 写在中间，后面的规则永远不会生效。

写 IP 规则时加 no-resolve。否则内核为了匹配会先解析域名，规则还没生效就产生了一次 DNS 查询。

国内域名不要一律走代理。CDN 会按来源调度，绕一圈反而更慢，还会让部分服务触发风控。

fake-ip 模式下 ping 通不代表真实可达。它返回的是保留地址段中的假地址，只用于把连接引到内核。用真实 IP 查询页验证出口，不要用 ping 结果判断。

IPv6 会绕过只处理 IPv4 的规则。双栈网络下，如果规则只写了 IPv4 网段，或者代理没有可用的 IPv6 出口，部分连接会直接走本地 IPv6，形成泄漏。检查方法是在启用代理后访问 IPv6 测试页，看返回地址是否属于本地运营商。处理方式有两种：关闭系统 IPv6，简单但会影响依赖 IPv6 的服务；让内核同时接管 IPv6 并在节点侧启用，完整但要求节点支持。按你的实际网络选择，不要默认关掉。

## 技术参数对比大表

这张表把新手最常遇到的参数放在一起。每行都标注单位、测量口径与数据性质。数据性质分四类：协议规定指标准文档写死的值，现场可测指你用工具能重复测出的值，服务方声明指只能引用对方说法的值，示例假设指本文为演示计算而设，并非实测数据。

| 参数 | 所在层 | 典型取值与单位 | 变化后的直接后果 | 测量口径 | 数据性质 |
| --- | --- | --- | --- | --- | --- |
| MTU | 链路层与网络层 | 1500 字节，PPPoE 为 1492 字节 | 超过路径 MTU 的大包被丢弃，网页能开、下载卡住 | 用禁止分片的探测包逐级试探 | 协议规定 |
| MSS | 传输层 | 1460 字节，等于 MTU 减 40 字节 | 与路径不匹配时分片或丢包 | 由 MTU 减 IP 头与 TCP 头推算 | 协议规定 |
| RTT | 传输层与应用层 | 毫秒，常见几十到几百 | 影响握手与首屏，不直接等于下载速度 | 同一目标多次采样取中位数 | 现场可测 |
| 抖动 | 传输层 | 毫秒，相邻采样 RTT 的偏差 | 语音、游戏、会议先受影响 | 连续采样后计算偏差 | 现场可测 |
| 丢包率 | 网络层 | 百分比 | 触发重传，吞吐下降，表现为卡顿 | 固定包数与大小的连续探测 | 现场可测 |
| 单流吞吐 | 应用层 | Mbps 或 MB/s | 决定单个下载或视频的码率上限 | 单连接持续传输取稳定段 | 现场可测 |
| 建连往返 | 传输层 | RTT 次数，TLS 1.3 为 1 次 | 每次新建连接多等一个往返 | 抓包数握手包个数 | 协议规定 |
| DNS 查询时延 | 应用层 | 毫秒 | 首屏变慢，解析失败则整站打不开 | 解析同一域名的多次采样 | 现场可测 |
| 订阅更新间隔 | 应用层 | 小时 | 越短越及时，也越容易被限流 | 看客户端设置与日志时间 | 服务方声明 |
| 并发设备数 | 服务层 | 台或连接数 | 超限时新设备连不上或频繁掉线 | 多设备同时在线观察 | 服务方声明 |
| 流量倍率 | 计费层 | 倍数 | 实际扣减等于用量乘倍率 | 对比客户端统计与账单扣减 | 服务方声明 |
| 系统代理覆盖率 | 应用层 | 百分比 | 覆盖率低时只有部分应用走代理 | 按应用清单逐个验证 | 现场可测 |
| TUN 路由条目 | 网络层 | 条 | 条目异常会导致断网或绕过 | 对比开启前后的路由表 | 现场可测 |
| 证书有效期 | 应用层 | 天 | 过期或时间偏差会导致握手失败 | 查看证书详情与系统时间 | 协议规定 |

读表时注意三个口径问题。

Mbps 与 MB/s 差八倍。标称 100 Mbps 约等于 12.5 MB/s，浏览器下载面板显示的是后者。把两个单位混着比较，会得出完全相反的结论。

GB 与 GiB 差约百分之七。服务方按十进制 GB 计费，操作系统按二进制 GiB 显示，100 GB 在系统里看起来只有 93 GiB 左右。差额来自换算，不是被偷了流量。

延迟低不等于速度快。延迟描述往返时间，吞吐描述单位时间能传多少。卫星链路延迟很高但带宽够用，拥塞链路延迟正常但吞吐很低。两个指标要分开测。

## 决策树：先判断你需要哪一类方案

下面这棵树按你手里的资源分流，走到叶子节点再回到对应章节。它不评价任何服务，只判断你该先做哪件事。

```text
起点：你现在有什么
├─ 没有任何客户端
│  ├─ 主要用手机
│  │  ├─ iPhone → 第 4 节 iOS 段，先确认商店地区
│  │  └─ Android → 第 4 节 Android 段，只装一个客户端
│  └─ 主要用电脑
│     ├─ 能装驱动、愿意授权 → 系统代理起步，必要时再开 TUN
│     └─ 公司电脑、不能装驱动 → 只用便携版与系统代理
├─ 有客户端，没有可用订阅
│  ├─ 预算为零
│  │  ├─ 愿意按方法核验 → 第 13 节，逐项记录证据
│  │  └─ 不愿意核验 → 停在原地，不要注册
│  └─ 能接受每月小额支出
│     ├─ 用量低于 20 GB → 先看流量包与最短周期
│     └─ 用量高于 100 GB → 比较月付与季付，不买年付
└─ 有订阅，但不稳定
   ├─ 全部节点都失败 → 查本地网络、系统时间与订阅更新
   ├─ 部分节点失败 → 查协议、端口与 UDP 是否被拦
   └─ 特定网站失败 → 查规则、DNS 与目标站风控
```

树上有三个常见误判，提前说明。

订阅过期被当成节点全挂。节点列表还在，延迟测试却全部超时，先看订阅的到期时间与更新日志，再看节点。

DNS 故障被当成节点故障。节点延迟正常，网页就是打不开，多半是解析环节出了问题。第 10 节把两者分开。

目标站限速被当成线路差。只有某一个网站慢，其他站点正常，先换目标站点对照，再怀疑线路。

## 数据是怎么走的：协议与网络原理

这一节解释五个基础件：代理握手、TCP 与 UDP、TLS、QUIC、DNS 与 MTU。看懂之后，第 10 节的故障树才有判断依据。

### 代理握手：先说明要去哪

本地代理入口接受两种常见握手。SOCKS5 在 RFC 1928 中定义，支持认证与 TCP、UDP 转发；HTTP CONNECT 是 HTTP 的隧道方法，在 RFC 9110 中定义。两者都只负责说明目标地址与端口，不负责加密。加密由后面的代理协议与 TLS 完成，这是两层不同的事。

```text
浏览器
  │ HTTP 请求
  ▼
本地入口 127.0.0.1:端口
  │ SOCKS5 / HTTP CONNECT：只说明要去哪
  ▼
内核：匹配规则，选定出站
  │ 代理协议封装（VLESS / VMess / Trojan / Shadowsocks）
  ▼
传输层：TLS over TCP，或 QUIC over UDP
  ▼
网络层：加密后的字节流
  ▼
本地网络 → 运营商 → 跨境链路 → 出口服务器 → 解密 → 目标站点
```

握手失败与传输失败要分开看。本地入口连不上，是客户端没启动或端口不对；本地入口能连、节点握手超时，是地址、端口、凭据或网络拦截的问题；握手成功但网页打不开，才是 DNS 与规则的问题。

### TCP 与 UDP

TCP 提供有序、可靠、带重传的字节流，代价是握手与拥塞控制。UDP 不保证顺序与到达，代价由应用自己承担。代理协议可以跑在 TCP 上，也可以跑在 UDP 上。

QUIC 把可靠传输做在 UDP 之上，因此同时具备 UDP 的穿透特征与接近 TCP 的可靠性。网络管理员可以按协议类型限制 UDP，这时依赖 UDP 的功能先坏：QUIC 站点回退到 TCP、语音与游戏卡顿、部分视频连接失败。TCP 通常更容易通过，但握手与重传开销更大。

### TLS 与证书

TLS 1.3 在 RFC 8446 中定义，握手通常一个往返完成。客户端验证证书链、域名与有效期，任何一项不匹配都会终止连接。TLS 提供加密与身份验证，它不隐藏你连接了哪个 IP，也不隐藏流量大小与时间。

```text
TCP + TLS 1.3（1-RTT）
客户端                                服务器
  │──── TCP SYN ─────────────────────►│
  │◄─── SYN-ACK ──────────────────────│
  │──── ACK ──────────────────────────►│
  │──── ClientHello + 密钥共享 ───────►│
  │◄─── ServerHello + 证书 + Finished ─│
  │──── Finished + 首个请求 ──────────►│
  │◄─── 响应 ──────────────────────────│

QUIC（TLS 1.3 内嵌，1-RTT）
客户端                                服务器
  │──── Initial（含 ClientHello）─────►│
  │◄─── Initial + Handshake ───────────│
  │──── Handshake + 首个请求 ─────────►│
  │◄─── 响应 ──────────────────────────│
```

握手包里能看到服务器证书的域名与有效期，所以“证书错误”往往比“连接超时”提供了更多信息。第 10 节会按这两类错误分别排查。

### QUIC 与 REALITY

QUIC 在 RFC 9000 中定义，把传输与加密合并，减少建连往返。它的丢包恢复策略与 TCP 不同，在高丢包链路上可能更稳，也可能因为 UDP 被限速而更差。可用性取决于路径，不取决于宣传。

REALITY 是一类借鉴真实站点握手特征的方案，目的是让代理握手更难与普通 TLS 流量区分。它不改变加密的基本原理，也不提供匿名。把它放在伪装层理解就够了，它不解决线路质量，也不解决本地 DNS 问题。

### DNS 与 MTU

DNS 默认是明文 UDP 查询，端口 53。明文查询可被观察与篡改，表现为返回错误地址、超时或跳到无关页面。加密 DNS 使用 DoH 或 DoT，把查询放进 TLS，但解析服务方仍能看到你查了哪些域名。

```text
路径 A 本地解析
应用 → 系统解析器 → 运营商 DNS → 权威服务器 → 返回地址
                    （明文，可被观察与篡改）

路径 B 远端解析
应用 → 内核 → 加密隧道 → 出口服务器解析 → 目标站点

路径 C 加密解析
应用或内核 → DoH（443）或 DoT（853）→ 解析服务 → 返回地址
```

MTU 是单个链路层帧能承载的最大字节数。以太网常见 1500，PPPoE 拨号减到 1492，再叠加隧道封装还会更小。路径上任何一段装不下又不允许分片，包就被丢弃。表现很有特征：小请求能通，大响应卡住，图片加载一半，登录提交失败。

```text
以太网 MTU 1500
  IP 头 20 + TCP 头 20 → MSS 1460
  PPPoE 再减 8 → MTU 1492，MSS 1452
  WireGuard 类封装再减约 60 至 80 → MTU 1420 附近
  超过路径 MTU 且禁止分片 → 大包被丢弃
```

判断方法：用逐步增大的包做禁止分片探测，找到能通过的最大值，再把接口 MTU 设到该值附近。不要一上来改到 1200，过小会降低效率，也会让某些网站直接拒绝连接。

## 连接失败的分层排查

按层排查的意思是每次只改一个变量。先确认现象属于哪一层，再做该层最小的验证动作。频繁换节点会同时改变多个变量，让你失去对照，最后说不清是哪一步修好的。

| 层 | 观察点 | 快速判断 | 下一步 |
| --- | --- | --- | --- |
| 本地网络 | 其他设备能否上网，热点是否正常 | 都断，先修本地网络 | 重启路由，换手机热点 |
| 客户端进程 | 进程是否存在，CPU 是否异常 | 进程不在，属于启动失败 | 查依赖、权限、配置语法 |
| 本地入口 | 端口是否监听，系统代理指向哪 | 端口不通，接管没有生效 | 换端口，重启客户端 |
| 节点握手 | 延迟测试结果，日志里的握手记录 | 全部超时，地址或网络被拦 | 换协议，确认 UDP 是否可用 |
| 解析与规则 | 域名解析结果，出口 IP | 解析错看 DNS，IP 对看规则 | 改 DNS，检查规则命中 |

```text
现象：浏览器打不开网页
├─ 1 本地网络
│  ├─ 手机热点也打不开国内网站 → 本地网络或 DNS 故障
│  └─ 热点正常 → 进入下一层
├─ 2 客户端
│  ├─ 进程不在 → 启动失败：依赖、权限、配置语法
│  └─ 进程在 → 本地端口是否监听
│     ├─ 未监听 → 端口冲突或配置未加载
│     └─ 已监听 → 进入下一层
├─ 3 节点握手
│  ├─ 全部节点超时 → 地址、端口、防火墙、UDP 被拦
│  ├─ 证书错误 → 系统时间、证书链、域名不匹配
│  └─ 握手成功 → 进入下一层
└─ 4 解析与规则
   ├─ 域名解析失败 → DNS 设置、污染、域名拼写
   ├─ 解析成功但连接超时 → MTU、出口拥塞、目标站限速
   └─ 出口 IP 与节点地区不符 → 规则未命中或泄漏
```

五分钟初筛，按顺序做，每步只记录结果不改配置：

1. 用另一台设备或手机热点访问一个国内站点，确认本地网络正常。
2. 打开客户端日志，找到第一条错误，不要从最后一条读起。
3. 确认系统代理指向的地址与端口，和客户端显示的一致。
4. 做一次节点延迟测试，区分全部失败与部分失败。
5. 查一个域名的解析结果，再查出口 IP，两项分别记录。
6. 只改一个变量后重测，改之前写下预期结果。

日志里的关键字比界面状态可靠。

| 关键字 | 常见含义 | 优先检查 |
| --- | --- | --- |
| timeout | 握手或请求无响应 | 地址端口、防火墙、UDP 限制 |
| connection refused | 端口未监听或对端拒绝 | 本地入口、节点端口 |
| certificate | 证书验证失败 | 系统时间、证书链、域名 |
| no such host | 域名解析失败 | DNS 配置、拼写、污染 |
| deadline exceeded | 超过等待时间 | 链路质量、DNS、MTU |
| permission denied | 权限不足 | TUN 授权、端口占用、文件权限 |

## 成本模型与预算测算

把标价换成可比较的数字，只需要四个公式。

- 单位流量成本 = 周期总价 ÷ 周期计费流量，单位元每 GB。
- 有效月成本 = 总价 ÷ 实际使用月数，单位元每月。
- 设备摊薄成本 = 有效月成本 ÷ 可用设备数，单位元每台每月。
- 含时间成本 = 现金支出 + 每月排障小时 × 时薪。

下表全部为测算假设，不代表任何服务的报价，也不代表市场行情。

| 参数 | 假设值 | 说明 |
| --- | --- | --- |
| 月付价格 | 10 元 | 仅用于演示公式 |
| 月计费流量 | 100 GB | 按十进制 GB 计 |
| 节点倍率 | 1 倍 | 高倍率节点单独折算 |
| 每月排障时间 | 2 小时 | 免费方案常见区间 |
| 时间单价 | 30 元每小时 | 按个人收入替换 |

例一，单位流量成本。假设月付 10 元、计费流量 100 GB，则 10 ÷ 100 = 0.10 元每 GB。若其中 30 GB 走了 2 倍率节点，计费量变成 30 × 2 + 70 = 130 GB，同样的钱只买到约 77 GB 的实际流量，单位成本升到 0.13 元每 GB。

例二，年付盈亏平衡。假设年付 100 元，用满 12 个月，有效月成本 8.33 元，低于 10 元月付。若只用了 5 个月就停用，100 ÷ 5 = 20 元每月，比月付贵一倍。年付划不划算，取决于你实际会用几个月。折扣力度本身不决定结果。

例三，免费的时间成本。假设现金支出为 0，每月花 2 小时排障，时间单价 30 元，隐性成本就是 60 元每月。这个数字高于 10 元月付。免费是否省钱，要看你的时间有没有别的用途。

三个结论：

先算单位流量成本，再比较总价。总价低但流量更少的套餐，单位成本可能更高。

年付只在确定长期使用时才划算。服务终止、线路降级与条款变更都不受你控制，把未使用的月份按全价摊回去，才是真实成本。

把排障时间算进去。免费方案的时间支出经常超过省下的现金，尤其是需要反复找订阅的阶段。

## 术语表

界面与条款里的词，按三列对照。第三列写的是最容易混淆的地方。

| 术语 | 一句话解释 | 容易混淆的点 |
| --- | --- | --- |
| 客户端 | 你操作的图形程序 | 界面与内核是两个进程，关窗口未必停内核 |
| 内核 | 真正建隧道与转发的程序 | 版本与客户端不匹配会启动失败 |
| 订阅 | 返回节点清单的地址 | 它返回清单，节点才是连接目标 |
| 节点 | 一台可连接的入口 | 入口地址与线路走向是两回事 |
| 机场 | 提供节点与订阅的服务方 | 它是服务形态，不是某种协议 |
| 协议 | 客户端与节点之间的封装方式 | 协议与传输可独立更换 |
| 传输 | 承载代理协议的底层通道 | TCP 与 UDP 的可用性由路径决定 |
| 系统代理 | 操作系统提供的应用层代理开关 | 只对读取该设置的应用生效 |
| TUN | 接管网络层流量的虚拟网卡 | 需要更高权限，冲突也更多 |
| 分流 | 按规则决定流量走向 | 规则顺序错会让后面的规则失效 |
| DNS 泄漏 | 解析请求走了代理之外的路径 | 泄漏的是查询行为，网页内容仍由 TLS 保护 |
| fake-ip | 用假地址把连接引到内核 | ping 通不代表真实可达 |
| RTT | 一个往返的耗时 | 低延迟不代表高吞吐 |
| 丢包 | 发出但未到达的包的比例 | 少量丢包对吞吐影响可能很大 |
| 倍率 | 计费时对用量乘的系数 | 高倍率节点会加快余额消耗 |
| 并发 | 同时在线或同时连接的数量 | 按 IP 与按设备计数结果不同 |
| 重置日 | 流量额度恢复的日期 | 与套餐到期日通常是两件事 |
| 退款窗口 | 可以申请退款的期限 | 已用流量常被扣减后再退 |

## 核验方法与可复现条件

核验的目标是让另一个人按你的记录复现出同样的结果。做不到复现，结论就只能算个人感受。

五个必填要素：

- 时间。写到分钟，注明时区，跨天测试要分开记录。
- 环境。设备型号、系统版本、客户端与内核版本、网络类型与带宽。
- 单位。延迟用毫秒，吞吐用 Mbps，流量用 GB，注明十进制或二进制。
- 证据。截图、日志时间戳、原始输出，保留失败样本，不要只留成功样本。
- 步骤。从打开客户端到得出结果的操作顺序，别人能照着做。

流程分五步：

1. 核对来源。发布页、版本号、校验和三项对得上，才进入下一步。
2. 核对条款。日志政策、退款条件、可接受使用政策各读一遍，记录关键句。
3. 验证连接。按第 10 节的分层顺序确认客户端、入口、握手、解析四层都通。
4. 测量指标。同一时段采三次以上，记录中位数与最差值，标注是否高峰时段。
5. 复测。隔天再测一次，连续三天通过才进入候选。

记录表可以直接照抄，字段不要省。

| 字段 | 示例 | 单位或格式 |
| --- | --- | --- |
| 核验时间 | 2026-10-24 21:30 | 本地时间，注明时区 |
| 网络环境 | 家庭宽带，下行 300 Mbps | 上下行分开写 |
| 客户端 | 名称与版本号 | 精确到小版本 |
| 节点 | 地区与协议 | 不写具体服务名 |
| 出口 IP | 地区与 ASN | 以查询页结果为准 |
| 延迟 | 中位数与样本数 | 毫秒 |
| 吞吐 | 单流稳定段 | Mbps |
| 结论 | 通过、不通过、证据不足 | 三选一 |

判定门槛建议写死：连续三天、每天两个时段、延迟与抖动、丢包、吞吐四项都有记录，才算通过。任何一项缺失，结论写证据不足。这套方法在资源检测专题里有更细的展开，见[核验方法](/resource-check/#method)。

## 安全、隐私与合规边界

代理改变的是流量的出口，不改变你是谁。下面这张威胁模型表说明谁能看到什么，以及低成本的处理方式。

| 威胁 | 谁能看到 | 前提 | 缓解 |
| --- | --- | --- | --- |
| 出口流量元数据 | 节点运营方 | 你使用其节点 | 不在代理下登录敏感账号 |
| DNS 查询内容 | 本地运营商或解析服务方 | 明文解析 | 加密 DNS 或远端解析 |
| 同一网络监听 | 同网段的其他设备 | 明文协议或伪造证书 | 只用 TLS，拒绝安装根证书 |
| 账号关联 | 服务方与目标站点 | 同一账号或同一出口 | 账号隔离，分应用代理 |
| 设备失窃 | 拿到设备的人 | 配置与订阅未加密 | 磁盘加密，订阅单独保管 |
| 恶意安装包 | 打包与分发者 | 从非官方渠道下载 | 官方发布页，核对校验和 |

三类观察者叠加，能推断出的信息比多数人以为的多。出口运营方看到你访问的域名、时间与流量大小；本地运营商看到你连接了哪个出口地址；目标站点看到出口 IP 与请求特征。代理不提供匿名，也不消除这些元数据。

合规部分只说边界，不给操作指导。不同司法辖区对代理工具、跨境访问与内容服务的规定不同，使用前自行确认当地法律、服务条款与可接受使用政策。本文不提供规避实名制、规避执法调查或隐藏违法行为的方法。

服务方的可接受使用政策通常禁止垃圾邮件、网络攻击、盗版分发与欺诈交易。违反的后果一般是封号，已付费用按条款处理，多数情况不退。

最小化清单：

- 不用主邮箱注册非必要服务，邮箱别名足够。
- 手机号只在必需时提供，能跳过就跳过。
- 支付使用可限额的渠道，不保存完整卡信息。
- 不安装来源不明的根证书，不关闭 TLS 校验。
- 不在代理下登录银行、政务与主邮箱。
- 试用结束后撤销授权、删除配置、清理证书。

## 常见问题

### 免费梯子和机场有什么区别

免费梯子通常指一整套能用的方案，可能由开源客户端加免费节点组成。机场指提供节点与订阅的服务方，有免费档也有付费档。一个强调工具组合，一个强调供给方。你装在设备上的是客户端，连的是节点，节点由服务方维护。三个词混用不影响日常沟通，排障时要分开，否则会对着客户端找服务方的问题。把三者分开之后，遇到问题才知道该查客户端设置、订阅状态还是服务方公告。

### 客户端显示已连接，为什么网页还是打不开

已连接只说明本地进程与节点握手成功，不保证解析与分流正确。先确认系统代理指向本机端口，再查域名解析结果与出口 IP，最后看规则是否命中。也可能是目标站点风控或本地网络限制。按第 10 节的顺序逐层查，每步只改一个变量。直接换节点会让你失去对照，最后不知道是哪一步修好的。记录每一步的观察结果，下一次出问题可以直接对照，省掉重复试错。

### 同一个节点昨天能用今天不行

常见原因有四个：订阅更新后地址或凭据变了；节点被服务方下线；你的网络到该地址的路径被拦截或拥塞；系统时间偏差导致证书校验失败。先看订阅更新时间与日志第一条错误，再归类。全部节点同时失效，更像订阅或本地网络问题；只有一个节点失效，更像节点本身或路径问题。订阅显示已过期时，先续期或更换来源，再谈节点质量。

### 系统代理和 TUN 该选哪个

桌面端先用系统代理，配置简单，回退快，能覆盖浏览器与常见应用。需要覆盖不读代理设置的程序，或者要做分应用精细控制，再考虑 TUN。TUN 需要管理员权限，会和其他 VPN 或虚拟网卡冲突。手机授予的 VPN 权限接近 TUN，没有系统代理这个选项。先用低权限方案验证链路，再决定是否升级。两种模式可以随时切换，切换后重新验证一次出口 IP。TUN 解决的是覆盖范围，不负责提速。

### 订阅链接可以发给朋友吗

不建议。订阅链接通常带有你的账号标识，别人使用会消耗你的流量，也可能触发并发限制与风控，导致你自己的连接被断开。部分服务会把异常多用视为共享账号。要分享就分享方法，不要分享带凭据的链接。发现链接泄漏后，立即在服务方后台重置，并检查是否有异常用量。定期更换订阅地址，把损失限制在最小。分享给家人前，也要确认条款是否允许。

### 免费节点能用来登录账号或付款吗

不建议。免费节点的运营者、日志政策与中间人风险都无法核验，登录凭据与支付信息一旦经过不可信出口，后果由你承担。需要登录重要账号时，优先使用自己的移动网络或可信网络。必须使用时，至少开启两步验证，并且不要在同一会话里完成付款。账号安全的价值高于省下的订阅费用。确需在代理下登录时，先确认出口地区稳定，避免触发异地登录验证。

### 手机开代理后耗电快、后台掉线

代理需要维持长连接并持续加解密，耗电高于普通待机。后台被杀多来自系统省电策略，把客户端加入不受限制名单，关闭电池优化，允许后台活动。不要为了省电关闭 TLS 校验或改用明文协议。Wi-Fi 与移动网络切换时的短暂断流属于正常重连，可以在客户端里调整重连间隔。不同厂商的省电策略差异很大，调整后观察一晚再决定。若仍然掉线，检查是否同时开了两个 VPN 类应用。

### 需要手动改 DNS 吗

多数情况下不需要。客户端自带的 DNS 设置已经能处理解析与分流，手动改系统 DNS 容易和客户端冲突。出现解析失败、污染或国内站点变慢时，再按第 6 节区分是解析路径问题还是规则问题。改之前记录原值，改完只测一个域名，确认有效再扩大范围。一次改多个设置，会失去排查依据。改完 DNS 后清一次缓存，否则旧结果还会生效一段时间。出现新问题就改回原值，保留可回退的状态。

### 节点延迟低就一定快吗

不一定。延迟描述往返时间，吞吐描述单位时间传输量。延迟低但带宽被限速的节点，下载仍然慢；延迟高但带宽充足的节点，看视频可能更顺。测速要同时看单流吞吐、丢包与抖动，并在同一时段对比。只看延迟数字容易被表面数据误导，尤其是延迟测试本身只发很小的包。测试时固定目标端点与时段，结果才有可比性。单次测速的偶然性很大，至少取三次中位数。

### 免费客户端会不会偷数据

闭源客户端无法从代码层面验证行为，开源客户端也可能被第三方重新打包。降低风险的做法是只从官方发布页下载、核对校验和与签名、检查权限请求是否与功能匹配。即使客户端可信，节点运营方仍能看到出口流量的元数据。软件可信与服务可信是两件事，需要分别判断。核对发布页的仓库地址与签名，比看界面像不像官方更可靠。安装后检查它申请了哪些权限，与功能对不上的直接卸载。

### 什么时候该从免费转到付费

出现下面任意两条就该考虑：每月排障超过两小时；关键工作因断线受阻；需要稳定登录重要账号；设备数超过免费额度；免费来源的条款与主体无法核验。先用最短周期与最小额度验证，再决定是否长期付费。不要因为折扣直接买年付，把未使用的月份按全价摊回去再比较。把候选服务的单位流量成本、退出条件与排障时间列成表，再和免费方案对比。结论可能是不买，这也算有效判断。
