# 免费机场

> 直接结论：截至 2026-10-24，本站合格免费机场条目为 0 条，下一次复核安排在 2026-11-07。免费机场的“免费”通常由限时试用、注册赠送、公益节点、商业引流或聚合站转发承担，每一种都带领取条件、额度口径和失效时间。没有同时满足五项收录标准的条目，本页不列出任何节点。

## 1. 直接结论与适用边界

本页处理三个问题：免费机场能不能用，值不值得提交信息，失效之后怎么办。答案按条件和证据给出，不按体验形容词给出。

收录状态先写在前面。审核日期 2026-10-24，结果 0 条，下次复核 2026-11-07。审核范围包括机场提供的免费额度、公开免费节点列表、限时试用与邀请活动、社区共享订阅，以及聚合站的二次转发。开源客户端软件本身不在计数范围内，它们由各自的官方仓库发布，与机场供给是两件事。

四条结论：

1. 免费供给有五种常见来源，成本承担方各不相同。限时试用与注册赠送由运营方的获客预算承担，公益节点由个人或社区承担，商业引流把免费额度当作广告成本，聚合站转发不生产资源，只搬运上游内容。
2. 免费额度必须同时写清流量、设备与期限。三项里缺一项，额度就无法复核。只写“送 100G”而不写有效期、重置规则、是否按倍率结算的页面，不构成可核验的额度说明。
3. 免费方案的成本会转移，不会消失。转移方向有三个：你的时间，你的账号与支付信息，以及链路的稳定性。第 7 节给出把这三项折成钱的公式。
4. 节点失效有明确的工程原因。入口 IP 被封、SNI 被阻断、证书过期、订阅令牌吊销、出口超售、内核版本错配，都会让同一条订阅在几小时内从可用变成不可用。

“机场”是中文社区对订阅制代理服务的称呼，与航空运输无关。口语里的“免费机场”至少对应三种东西：提供免费额度的商业服务、公开分享的节点列表、免费的客户端软件。三者的供给方、失效方式和风险都不一样。本站按“是否提供可导入的订阅或节点配置”来界定，客户端软件归入[免费代理软件](/proxy-software/)专题。

时间边界需要单独说明。免费资源的有效期通常以天计，订阅令牌可能随时吊销，活动名额可能在一小时内发完。本页的所有状态都以核验日为准，不构成核验日之后的可用性承诺。读者在任何时候拿到的配置，都要按第 8 节的流程重新核验一次。

## 2. 这个专题解决什么问题

### 谁该读

四类读者能从本页得到可直接使用的东西。

第一类是第一次搜索“免费机场”的人。你需要知道注册之后会拿到什么、要交出哪些信息、额度按什么口径计算，以及页面上的“免费”是否附带支付方式。第 3 节到第 5 节解决这部分。

第二类是已经收藏了几个订阅链接的人。链接还能打开，节点却连不上，问题可能出在令牌、DNS、协议参数或本地网络。第 6 节到第 8 节给出一条按层排查的顺序，避免反复更换订阅。

第三类是预算在 10 元到 20 元之间的人。你需要把免费额度的时间成本与低价套餐的现金成本放在同一张表里比较，只比较标价会漏掉时间成本。第 7 节给出公式与算例。

第四类是帮别人配置或写内部方案的人。你需要一份可以复用的验收清单，记录核验时间、环境、额度口径和退出条件。第 8 节的审核记录表可以直接改成你自己的模板。

### 谁不该读

需要 7×24 稳定链路的人，不该把免费方案放进生产环境。免费供给没有服务水平协议，也没有可追责的恢复时间。线上业务、远程办公的关键链路、需要长时间保持会话的任务，应当直接进入付费方案或自建方案。

需要匿名的人，也不该把希望放在免费代理上。代理改变的是出口 IP，账号、支付、设备指纹与行为轨迹之间的关联仍然存在。第 9 节会解释哪些信息仍然可见。

想直接拿节点的人会失望。本页不发布节点、不发布订阅、不提供“内部渠道”，也不评价具体品牌。具体机场的资料与测速截图集中在[42 家机场品牌库](/airports/)，本页只提供判断方法与一份诚实的收录状态。

- 不回答“这个节点现在能不能连”。节点状态以分钟变化，页面无法承担实时性。

## 3. 概念与实体关系

### 三种“免费”要分开

同一个页面上可能出现三种免费：软件免费、额度免费、时间免费。软件免费指客户端与内核开源，下载不付费；额度免费指运营方给出一定流量或时长；时间免费指公益节点由他人承担成本，使用者不付费也不承担维护。三者的可持续性差别很大。软件免费可以长期成立，因为成本由使用者自己的设备承担；额度免费依赖运营方的获客预算，预算停止，额度就停止；时间免费依赖个人或小社区的持续投入，投入中断，节点就消失。

判断一条信息属于哪一类，可以问四个问题：

1. 服务器与带宽由谁付费？
2. 免费额度是否有明确的有效期与重置规则？
3. 领取是否需要提交邮箱、手机号、支付方式或邀请关系？
4. 条款是否允许个人使用，是否禁止转售与共享？

四个问题都能在公开页面找到答案时，这条信息才进入核验流程。找不到答案时，它只能当作线索，不能当作资源。

图里有一个容易被忽略的方向：订阅链接与节点入口是两条独立通道。订阅链接失效，节点可能仍然可连；节点入口被封，订阅仍然可以更新，只是列表里的地址全部不可达。排查时先确认坏在哪条通道，能省掉大量重复导入。

### 客户端免费与服务免费

客户端是本地程序，服务端是持续付费的服务器。开源客户端不产生服务器成本，也不为任何节点背书。把客户端下载页当成免费节点来源，是最常见的误解之一。判断方法很简单：看这个页面是否提供可导入的订阅地址或节点参数，是否说明流量与期限。只有安装包，没有服务端信息，它属于软件，不属于机场。

### 节点在线与可以发布

端口可连接只说明有一次 TCP 握手成功。可发布还要求来源可追溯、额度与期限明确、条款允许引用、两个时点可复核。四项里缺任何一项，节点仍然可能在线，但不会进入本站列表。在线是技术状态，可发布是编辑状态，两者需要分开记录。

### 赠送流量与长期可用

赠送流量通常绑定新账号、首次登录或特定活动。额度用尽、活动结束、账号被判定为滥用，都会让同一条订阅停止工作。把赠送额度当成长期方案，会在最需要网络的时候失去连接。合理的用法是把它当作一次有期限的验收，验收结束就回到预算与需求本身。

## 4. 技术参数对比

这张表只收录公开规范与官方文档能够确认的机制，不收录速度、延迟、节点数量与可用率。免费供给的线路质量随时间、地区和时段变化，任何写死的性能数字都无法复核。表的作用是帮助读者看懂订阅里的字段，判断某个客户端能否解析，以及在失败时知道该看哪一层。

| 名称 | 传输与端口口径 | 认证要素 | 握手往返 | MTU 与分片敏感度 | 订阅与客户端形态 |
| --- | --- | --- | --- | --- | --- |
| Shadowsocks（AEAD） | TCP，端口自定义，高位端口常见 | 预共享密码与加密方式 | 1 次（无 TLS 时） | 中，UDP 转发需处理分片 | `ss://` 链接，常见于 Base64 列表 |
| VMess | TCP、WebSocket 或 gRPC，端口自定义 | UUID 与时间戳，旧版另有 alterId | 1 次起，TLS 与 WebSocket 另计 | 中，依赖底层传输 | `vmess://` Base64 JSON |
| VLESS | TCP、WebSocket、gRPC 或 REALITY | UUID，协议本身不加密 | 1 次，加 TLS 后为 2 次 | 中 | `vless://` 查询参数 |
| Trojan | TCP 加 TLS，常用 443 端口 | 密码与有效证书 | 2 次（TCP 与 TLS 各 1 次） | 中 | `trojan://` 链接 |
| Hysteria2 | UDP 与 QUIC，高位端口常见 | 密码或证书 | 1 次，会话恢复可 0 次 | 高，依赖路径 MTU 探测 | `hysteria2://` 链接 |
| TUIC | UDP 与 QUIC | UUID 与密码 | 1 次 | 高 | `tuic://` 链接 |
| WireGuard | UDP | 静态公钥对，Noise IK 握手 | 1 次 | 高，IPv4 下开销约 60 字节 | 配置文件，非机场订阅主流 |
| SOCKS5 | TCP，UDP ASSOCIATE 可选 | 无认证或用户名密码 | 1 次加协商与请求 2 次 | 低 | 本地代理协议，不作为订阅格式 |
| HTTP CONNECT | TCP | 代理认证可选 | 2 次（TCP 与请求各 1 次） | 低 | 系统代理常见 |
| Base64 订阅 | HTTPS 拉取 | URL 令牌 | 1 到 2 次 | 不涉及 | 通用链接列表，客户端负责解码 |
| Clash YAML | HTTPS 拉取 | URL 令牌，可能按 User-Agent 区分 | 1 到 2 次 | 不涉及 | Mihomo 系客户端直接解析 |
| sing-box JSON | HTTPS 拉取 | URL 令牌 | 1 到 2 次 | 不涉及 | sing-box 系客户端直接解析 |

表注：

- 单位：握手往返以 RTT 计，不含 DNS 解析时间；MTU 与协议开销以字节计；端口为社区惯例，服务端可以修改。
- 口径：握手往返只统计传输层与安全层，不统计应用层重试；0-RTT 仅指会话恢复，存在重放风险，不能当作默认能力。
- 数据性质：按公开规范与官方文档整理，非实测。表中没有速度、延迟与可用率数值，免费供给无法在稳定条件下复现这些指标。

| 商业引流 | 广告与后续转化 | 免费档限速或限量 | 长期存在但可改条款 | 1 到 2 台 | 免费档作为升级入口 |
| 聚合站转发 | 上游运营方 | 继承上游 | 通常短于上游 | 继承上游 | 令牌替换、过期、篡改 |

表注：这一表描述结构口径，不构成市场报价。“示例 3 到 7 天”与“1 到 3 台”只用于说明口径差异，任何具体服务都要以其核验当日的条款为准。

## 5. 决策树

决策树解决一个具体问题：在合格免费条目为零的情况下，怎么按需求选路径。树的顺序是先定期限，再定维护意愿与预算，最后写退出条件。它的作用是逐层排除，不承担推荐功能，每一层都在减少不适合的选项。

```text
开始：你需要一条可用的代理链路
│
├─ 第 1 层：使用期限
│  ├─ 7 天以内（旅行、应急、临时项目）
│  │  └─ 第 2 层：能否接受每天花 10 分钟维护
│  │     ├─ 能
│  │     │  └─ 第 3 层：是否已有可复核的免费来源
│  │     │     ├─ 有 → 按第 8 节核验，同时准备一个低价备用
│  │     │     └─ 无 → 公开免费列表只作应急线索，不当作长期方案
│  │     └─ 不能
│  │        └─ 第 3 层：预算是否达到 10 元
│  │           ├─ 是 → 周付或小流量月付
│  │           └─ 否 → 运营商漫游、本地网络，或把需求推迟
│  ├─ 1 到 6 个月（日常网页、办公、轻度视频）
│  │  └─ 第 2 层：是否存在每月可核对额度的来源
│  │     ├─ 有
│  │     │  └─ 第 3 层：条款是否允许个人使用且不转售
│  │     │     ├─ 是 → 进入五项核验，通过才用
│  │     │     └─ 否 → 放弃该来源
│  │     └─ 没有
│  │        └─ 第 3 层：能否接受每周失效 1 次以上
│  │           ├─ 能 → 免费额度加备用方案
│  │           └─ 不能 → 10 到 20 元档月付
│  └─ 6 个月以上（长期）
│     └─ 第 2 层：是否愿意承担账号与支付信息
│        ├─ 愿意
│        │  └─ 第 3 层：年付折扣是否低于月付的 10 倍
│        │     ├─ 是 → 先月付 1 个月验证，再考虑年付
│        │     └─ 否 → 月付或流量包
│        └─ 不愿意
│           └─ 自建或本地网络，不进入免费机场队列
│
└─ 第 4 层：所有分支共用，写下退出条件
   ├─ 连续 3 天不可用 → 启用备用方案
   ├─ 条款新增扣费或自动续费 → 立即取消
   ├─ 要求提交身份证、人脸或他人账号 → 停止使用
   └─ 需要关闭证书校验才能连接 → 停止使用
```

读这棵树时注意两点。第一，叶子上的“免费”只表示现金支出为零，时间成本与风险仍然存在，第 7 节会把它们折算成金额。第二，退出条件要在开始使用之前写下来，因为失效发生时人容易反复重装，计划里的切换点反而被跳过。

树的第 3 层有一个共同前提：任何来源都要先通过第 8 节的五项核验。核验不通过的来源，不管在哪一层出现，都直接排除。

## 6. 底层网络协议原理

免费节点失效时，读者最容易看到的是“连不上”三个字。实际失败点分布在域名解析、TCP 握手、TLS 握手、代理协议认证、出口转发五个位置。理解这条路径，才能把“节点坏了”拆成可验证的结论。

### 一次请求经过的五段

```text
[浏览器请求 https://example.com]
      │
      ▼
[1] DNS 解析
    系统解析器 → 递归解析器 → 权威服务器
    返回 A / AAAA 与 TTL，可能被污染，也可能按地区返回不同 IP
      │
      ▼
[2] 本地代理接管
    浏览器 → 127.0.0.1:7890（SOCKS5 或 HTTP CONNECT）
    客户端按规则决定 direct / proxy / reject
      │
      ▼
[3] 传输与安全握手
    TCP 三次握手 → TLS 1.3 握手（ClientHello → ServerHello → 证书 → Finished）
    或 QUIC 握手（传输与加密合并，1-RTT，恢复会话可 0-RTT）
      │
      ▼
[4] 代理协议认证
    内核按订阅参数发送协议头：UUID、密码、传输层字段
    服务端校验后建立转发，失败时返回关闭或静默丢弃
      │
      ▼
[5] 入口 → 中转 → 落地 → 目标站点
    落地以新的源 IP 访问目标，响应沿原隧道返回
```

五段里任何一段失败，用户看到的现象都可能是“转圈”。排查的价值在于定位到段，反复更换订阅只会重置线索。

### TCP、UDP 与拥塞控制

TCP 提供可靠传输，代价是三次握手、确认与重传。跨境链路的往返时延较大时，单条 TCP 连接的吞吐受拥塞窗口与往返时延共同限制，丢包会触发重传与窗口收缩。免费节点常被大量用户共享，出口拥塞时，单流速度下降得比专线明显。

UDP 不保证交付，也不维护连接状态。QUIC 在 UDP 之上实现可靠传输、加密与拥塞控制，把控制逻辑放到用户态。它的优势是握手次数少、连接迁移和多流复用；代价是部分网络对 UDP 限速或直接阻断，表现为“能连上但传不动”。免费服务通常没有能力为每个用户调优这条路径。

### TLS 1.3、SNI 与证书

TLS 1.3 把完整握手压缩到 1 个往返，ClientHello 里携带 SNI 与 ALPN。SNI 在默认配置下是明文，链路观察者可以据此判断目标域名；ECH 的部署范围有限，不能当作通用防护。会话恢复可以使用 0-RTT，但 0-RTT 数据存在重放风险，服务端需要额外策略。

证书校验是另一条边界。客户端如果被要求“关闭证书校验”才能连接，链路上的中间人就可以替换证书并读取内容。免费服务里出现这种要求时，应直接停止使用。证书过期、域名不匹配、链式证书缺失，都会让客户端在握手阶段报错，现象与“节点失效”很像。

### QUIC 与基于 UDP 的协议

QUIC 的传输规范、TLS 映射与丢包恢复分别由 RFC 9000、RFC 9001、RFC 9002 定义。它用连接 ID 支持网络切换，用流级多路复用减少跨流队头阻塞，并把加密握手与传输握手合并。Hysteria2 与 TUIC 都建立在 QUIC 之上，前者还提供可选的拥塞控制模式。部分模式在共享链路上可能挤占其他流量，服务端是否启用要以配置为准。

UDP 方案在受限网络中的表现差异很大。同一入口，TCP 443 可能稳定，UDP 高位端口可能被限速。判断方法应看小请求是否成功、大流量是否中断，客户端显示的延迟只能作参考。

### DNS 路径与污染

DNS 查询可能经过系统解析器、运营商递归、公共递归或加密解析。DoH 由 RFC 8484 定义，DoT 由 RFC 7858 定义，两者都只保护客户端到解析器这一段。ECS 扩展会把客户端子网传给权威服务器，用于就近调度，同时暴露部分网络位置。

污染的表现是返回错误地址或超时。判断时对比三组结果：系统解析器、加密解析器、直接连接已知 IP。三组不一致，问题更可能在解析；三组都失败，问题更可能在链路。TTL 也会制造假象，缓存未过期时，域名已经换了地址，客户端仍在用旧记录。

### MTU、分片与路径探测

```text
以太网 MTU = 1500 字节
┌────────────┬──────────┬──────────────────────┬──────────────┐
│ IP 头 20   │ UDP 头 8 │ WireGuard 头与标签 32│ 载荷         │
└────────────┴──────────┴──────────────────────┴──────────────┘
  1500 - 20 - 8 - 32 = 1440 字节（IPv4 理论上限）
  常见配置取 1420，为 PPPoE 与路径差异留出余量

QUIC 路径
┌────────────────┬────────────────┬───────────────────────────┐
│ QUIC 头与帧    │ AEAD 标签 16   │ 载荷                      │
└────────────────┴────────────────┴───────────────────────────┘
  DPLPMTUD 探测可用 MTU，避免 IP 分片
  中间设备丢弃大包时，握手成功但大文件传输停住
```

MTU 问题的典型现象是网页能打开、视频卡住、下载停在某个百分比。PPPoE 拨号把 MTU 降到 1492，移动网络与隧道又各有开销。路径 MTU 探测依赖 ICMP 反馈，部分网络屏蔽 ICMP，导致黑洞。客户端能否调整 MTU、是否启用分片，直接决定这类问题能否绕过。

### 代理握手与本地接管

本地这一层常用 SOCKS5 或 HTTP CONNECT。SOCKS5 由 RFC 1928 定义，用户名密码认证由 RFC 1929 定义；HTTP CONNECT 由 RFC 9110 定义。系统代理只影响遵守系统设置的应用，TUN 通过虚拟网卡接管路由，覆盖更广，也需要更高权限。免费订阅里的 `udp`、`tfo`、`mux` 字段在不同内核里的语义不完全一致，导入后要按客户端文档核对。

## 7. 成本模型与预算测算

免费方案的现金支出为零，总成本不为零。成本由三块组成：现金、维护时间、风险折算。把三块放在同一个单位上，才能与低价套餐比较。本节所有数字都是测算假设，用来演示算法，不构成市场报价或实测结果。

### 公式

```text
Q = 计费额度（GB，服务商口径）
m = 平均倍率（无量纲）
l = 链路损耗率（重传、握手失败、测速浪费，无量纲）
E = Q ÷ m × (1 - l)          可用流量（GB）
P = 套餐价格（元）
c = P ÷ E                     单位流量成本（元/GB）

n = 每月失效次数（次/月）
t = 单次修复时间（小时/次）
w = 时间价值（元/小时，测算假设）
T = n × t × w                 月时间成本（元/月）
R = 风险折算（元/月，含隐私、账号、支付风险）
C = P + T + R                 总拥有成本（元/月）
C_free = T_free + R_free      免费方案的现金项为 0
```

### 算例一：付费套餐的每 GB 成本

假设月付 10 元，计费额度 100 GB，平均倍率 1.0，损耗率 8%。可用流量 E = 100 ÷ 1.0 × 0.92 = 92 GB，单位成本 c = 10 ÷ 92 ≈ 0.109 元/GB。

同样的额度，如果 30% 的用量走 2 倍率线路，平均倍率变成 0.7 × 1 + 0.3 × 2 = 1.3。可用流量 E = 100 ÷ 1.3 × 0.92 ≈ 70.8 GB，单位成本升到 10 ÷ 70.8 ≈ 0.141 元/GB。倍率不改变标价，只改变额度消耗速度。

单位换算也会影响判断。服务商写 100 GB 时通常按十进制；如果客户端按 GiB 显示，100 GB 约等于 93.13 GiB。把两种单位混在一起比较，会得出错误的“额度缩水”结论。

### 算例二：免费额度的时间成本

假设免费额度每月 20 GB，每周失效 2 次，每次修复 15 分钟，时间价值按 40 元/小时计。月时间成本 T = 2 × 4.33 × 0.25 × 40 ≈ 86.6 元。按 20 GB 摊开，每 GB 的时间成本约 4.33 元，是算例一付费方案的约 40 倍。这里的风险折算 R 还没有计入。

这个算例说明一件事：免费方案是否省钱，取决于失效频率与你的时间价值，不取决于标价。每周修两次、每次一刻钟，一个月就是两个多小时。

### 算例三：流量包的月等效成本

假设一次性流量包 30 元、100 GB、不限时。月用量 U 决定它能用多久：月等效成本 = 30 × U ÷ 100。U 为 10 GB 时，月等效 3 元；U 为 50 GB 时，月等效 15 元；与 10 元月付持平的临界点是 U = 33.3 GB/月。

这个公式只适用于“不限时、不清零”的流量包。若流量包有固定有效期，先算有效期内的可用月数，再摊开。过期清零的流量包，实际单位成本要用“已用流量”作分母，不能用标称额度。

### 假设表

| 参数 | 符号 | 取值 | 单位 | 性质 |
| --- | --- | --- | --- | --- |
| 套餐价格 | P | 10 | 元/月 | 示例 |
| 计费额度 | Q | 100 | GB | 示例，十进制 |
| 平均倍率 | m | 1.0 或 1.3 | 无量纲 | 示例 |
| 链路损耗率 | l | 8% | 无量纲 | 假设 |
| 每月失效次数 | n | 2 | 次/月 | 假设 |
| 单次修复时间 | t | 0.25 | 小时/次 | 假设 |
| 时间价值 | w | 40 | 元/小时 | 假设 |
| 风险折算 | R | 0 | 元/月 | 未计入，便于对照 |

### 失效频率的敏感性

| 每周失效次数 | 每月失效次数（按 4.33 周） | 月时间成本 | 每 GB 时间成本（20 GB 额度） |
| --- | --- | --- | --- |
| 0 | 0 | 0 元 | 0 元 |
| 1 | 4.33 | 43.3 元 | 2.17 元 |
| 2 | 8.66 | 86.6 元 | 4.33 元 |
| 4 | 17.32 | 173.2 元 | 8.66 元 |

表注：时间成本按 t = 0.25 小时、w = 40 元/小时计算；每 GB 时间成本只分摊时间，不含现金与风险。失效次数翻倍，时间成本线性翻倍，这就是免费方案在长期使用中不便宜的原因。

把三块成本写在一张纸上，再决定要不要继续用免费方案。如果时间成本已经超过低价套餐的月费，继续等待免费资源就是负收益。第 11 节把这条判断接到其他专题。

## 8. 核验方法与可复现条件

本节的方法与[资源检测](/resource-check/#method)专题共用一套口径。核验的目标是让另一个人在同一时间、同一环境下得到同样的结论，一张好看的截图不足以作为证据。

### 五项发布标准

一条免费资源要同时通过五关，才会进入列表：

1. 运营方有可追溯的官方页面或公开主体信息。
2. 免费额度、有效期、设备数与使用条款可以同时核对。
3. 不要求不可撤销的敏感权限、异常支付信息或向第三方转发账号。
4. 至少在两个独立时点可复核，且核验当日仍能打开官方说明。
5. 允许引用核验结论，且不把付费解锁包装成免费领取。

五项里任何一项缺失，条目都保持未收录。缺一项与缺五项的处理相同，因为读者无法用缺失的信息做决定。

### 记录格式

| 记录字段 | 填写口径 | 示例 |
| --- | --- | --- |
| 核验时间 | UTC+8，精确到分钟 | 2026-10-24 14:30 |
| 网络环境 | 运营商、接入方式、是否双栈 | 家庭宽带，IPv4 与 IPv6 |
| 设备与系统 | 设备类型、系统版本 | Windows 11 |
| 客户端与内核 | 名称、版本号、获取来源 | 官方 Release 版本号 |
| 目标端点 | 域名或 IP、端口、协议 | 订阅域名与 443 端口 |
| 采样与次数 | 探测方式、次数、时间段 | TCP 探测 5 次，间隔 1 分钟 |

记录里不写“很快”“很稳”这类词。速度写 Mbps 或 MB/s，并注明单线程还是多线程；延迟写 RTT，并注明目标、时间与采样次数；可用性写探测成功率与观察窗口。没有这些条件的数字，不进入对比。

### 两个时点与下架

首次核验通过后，条目进入待复核状态，间隔不少于 24 小时再做第二次核验。第二次核验要确认三件事：官方页面仍可打开、额度与期限没有变化、条款没有新增扣费或转售限制。三项都通过，条目才进入列表；任一项变化，条目退回待复核。

超过 30 天未复核的条目自动降级为待复核，不再展示为可用。下架不删除记录，核验日期、失败原因与证据快照保留在审核日志里，方便下一次复核时对照。这套规则会增加编辑成本，但能避免把过期信息当成现状。

如果你要自己核验一条免费资源，按上面的记录格式做一遍，再看五项标准能否全部满足。不能满足时，把它当作线索，不要当作可用资源。

## 9. 安全、隐私与合规边界

免费服务的安全问题要放在威胁模型里看。对手至少有三类：掌握服务端的运营方、链路上的观察者、以及你设备上安装的客户端。资产包括账号、支付信息、浏览内容、设备权限与可被关联的身份。三类对手的能力不同，缓解手段也不同。

| 威胁 | 前提 | 影响 | 可观察证据 | 缓解 |
| --- | --- | --- | --- | --- |
| 运营方记录连接日志 | 服务端可控 | 时间、源 IP、目标域名被留存 | 隐私政策、条款、日志字段说明 | 不登录敏感账号，不使用主邮箱 |
| 链路观察者做流量分析 | 能观察入口流量 | 推断访问的域名与使用时段 | SNI 可见、包长与时段特征 | 优先选择支持 TLS 与混淆的配置 |
| 恶意客户端或改包 | 安装非官方版本 | 证书被替换、流量被劫持 | 签名不符、权限异常、来源不明 | 只从官方 Release 下载并校验 |
| 订阅令牌泄露 | 链接被转发或截图 | 额度被盗用、出口 IP 被共用 | 流量异常、设备列表变化 | 把订阅链接当作密码，定期更换 |
| 出口 IP 被目标站点风控 | 共享 IP 被滥用 | 验证码、登录失败、服务受限 | 状态码、验证页面、风控提示 | 更换出口或改用其他方案 |
| 支付信息被留存 | 绑卡或订阅 | 自动续费、扣费争议 | 收据、扣费记录、条款 | 使用限额支付方式，关闭自动续费 |

### 代理不承诺匿名

代理改变的是出口 IP。账号层仍然有邮箱、手机号、支付方式与设备指纹；网络层仍然有 SNI、IP、包长与时序；行为层仍然有登录时间、访问频率与内容偏好。三层里的任意两层组合，通常足以把一次访问与一个账号关联起来。HTTPS 保护内容，不隐藏你访问了哪个域名，也不隐藏你什么时候访问。

ECH 能加密 ClientHello 中的 SNI，但需要客户端、DNS 与服务端同时支持，部署范围有限。把它当作默认能力，会高估隐私水平。

### 证书校验不能关闭

客户端提示证书错误时，正确做法是核对域名、有效期与签发者，或者停止使用。关闭证书校验会让中间人替换证书变得容易，链路上的任何一方都能读取明文。免费服务出现“请关闭证书校验”的说明时，这本身就是风险信号，不需要再测试。

### 合规边界

不同司法辖区对代理工具、加密服务与跨境访问的规则不同。使用前需要自行确认当地法律、服务条款与可接受使用政策。本站不提供规避执法、规避实名制或绕过服务地区限制的操作指南。违反法律或服务条款的使用，不在本站的讨论范围内，也不受任何“隐私保护”承诺的庇护。

### 数据最小化

- 用独立邮箱注册，不使用主邮箱与主密码。
- 不绑定主要支付方式，能关闭自动续费就关闭。
- 只安装官方 Release，核对签名与版本号。
- 订阅链接不截图、不转发、不放进公开仓库。
- 停止使用后删除配置、撤销授权、修改相关密码。

这些动作不能消除风险，只能把风险压到可接受的范围。是否值得承担，取决于用途与替代方案的成本。

## 12. 常见问题

### 免费机场现在真的一个都没有吗？

本站的 0 条指收录状态，意思是本期没有条目同时满足五项发布标准。它不代表互联网上不存在免费服务，也不代表所有免费服务都不可用。限时活动、邀请码、已失效列表与需要付费解锁的方案都没有计入。下一次复核安排在 2026-11-07，只有出现可复核的新证据，数字才会变化。读者可以把 0 条理解为“本站暂不发布”，不能理解为“全网为零”。

### 注册送流量算免费机场吗？

要分情况。注册后不付款就能拿到可导入的订阅，且额度与期限写在公开条款里，属于注册赠送。只送折扣券、必须先充值、或赠送流量只能在付费套餐内使用，属于商业引流，不计入免费额度。判断标准是领取过程中是否出现不可撤销的支付授权。出现绑卡、预授权或最低消费时，这条资源的成本已经不为零。

### 公开免费节点列表为什么不能直接用？

列表通常缺少运营主体、条款与额度说明，节点地址在公开后很快被爬虫抓取和滥用。你无法确认出口由谁控制、是否记录日志、是否允许个人使用。它可以作为应急线索，不能作为长期方案，也不能进入本站收录表。需要使用时应先按第 8 节核验，记录两个时点的结果，并准备一条可回退的低价线路。

### 免费机场的订阅链接会泄露什么？

订阅链接里的令牌等同于账号凭证。拿到链接的人可以拉取节点列表、消耗额度、看到出口 IP，部分服务还能看到设备与连接记录。截图、转发到群里、提交到公开仓库都会造成泄露。把订阅链接当作密码管理，不截图、不共享，定期更换。怀疑泄露时，先在服务端重置令牌，再检查流量记录与设备列表。

### 免费额度一天能用多少流量？

取决于供给方的额度口径。日包按自然日重置，月包按计费周期重置，一次性包用完即止。还要看倍率与限速：标称 10 GB 在 2 倍率线路上只能支撑 5 GB 实际流量。没有写明重置时区与倍率的页面，无法计算日可用量，只能当作未知。估算需求时，可以按网页每小时 100 MB 到 300 MB、标清视频每小时 0.7 GB 到 1 GB 的区间做测算。

### 为什么白天能用晚上不能用？

常见原因是出口带宽被共享用户占满，晚高峰并发上升，单用户可用带宽下降。也可能是运营商在高峰时段对 UDP 或特定端口限速。判断方法是记录同一目标在 14 时与 21 时的吞吐与丢包，如果白天正常、晚上持续下降，问题更可能在出口拥塞，本地配置可以最后再看。连续记录三天，比单次测速更有说服力。

### 免费机场要求绑定支付方式正常吗？

绑定支付方式不违法，但它把免费变成了有条件的试用。需要看三件事：是否预授权、是否自动续费、取消后是否仍会扣费。条款里找不到取消路径，或取消入口只在付款后出现，应当停止。免费额度不应以不可撤销的支付授权为前提。已经绑定时，先关闭自动续费，再确认取消是否即时生效，并保存取消页面与邮件。

### 免费机场能解锁流媒体或 AI 服务吗？

不能仅凭“解锁”标签判断。流媒体与 AI 服务按 IP 信誉、地区与账号状态做风控，同一出口对不同用户的结果可能不同。免费节点共享 IP，被滥用的概率更高，遇到验证码与登录限制的机会也更高。需要稳定解锁时，应把这项需求单独评估，不要把它当作免费额度的默认能力。先确认目标服务是否允许该地区使用，再谈线路。

### 免费机场和免费 VPN 有什么区别？

机场通常提供订阅与多协议节点，客户端由用户自选；免费 VPN 通常是打包好的应用，协议与服务器由厂商控制。机场的免费额度多来自试用或赠送，VPN 的免费档多来自广告或功能限制。两者都可能记录日志，都需要看条款。概念差异在[免费梯子](/free-vpn/)专题里有更细的拆分。选择时先确认谁能看到你的流量与账号信息。

### 免费机场失效后先检查什么？

先看订阅能否更新，再看节点入口端口是否可达，然后看 TLS 握手与协议认证，最后看出口 IP 是否变化。顺序从本地到远端，避免一上来就重装客户端。客户端日志里的错误码比“连接失败”四个字有用得多。完整流程见[免费机场无法使用时怎么办](/guides/free-airport-not-working)。每步只改一个变量，才能知道是哪一步恢复了连接。

### 10 元档套餐比免费方案贵在哪里？

贵在可预期的额度、较少的维护次数与可追责的退款条款。按第 7 节的算例，免费方案每月两次失效、每次 15 分钟，时间成本约 87 元。10 元档的现金支出更高，总成本可能更低。判断标准应落在总拥有成本上，标价只说明现金部分。预算档位的拆解见[便宜梯子](/budget-vpn/)。如果每月只用几 GB，流量包可能更合适。

### 下一次复核是什么时候，会更新什么？

下次复核安排在 2026-11-07。会重新检查已有证据是否仍可打开、条款与额度是否变化、是否出现同时满足五项标准的新材料。没有合格条目时，数字继续保持 0，并更新复核日期与缺口说明。复核不等于一定新增条目，也不承诺任何具体服务会通过。复核记录会保留在页面的审核表中，方便对照变化。

1. 想自己核验一条资源：先读[资源检测方法](/resource-check/#method)，按记录格式做两次复核。
2. 已经连不上：走[免费机场无法使用时的排查流程](/guides/free-airport-not-working)，从订阅、DNS、握手到出口逐层定位。
3. 准备改用低价方案：用[便宜梯子](/budget-vpn/)的单位成本公式，把现金、时间与风险放在同一张表里比较。
