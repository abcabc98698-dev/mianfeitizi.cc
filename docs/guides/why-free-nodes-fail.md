# 免费节点为什么经常失效？服务成本、限流和连接稳定性分析

> 直接结论：免费节点短命，通常由四层原因叠加。供给方的带宽与 IP 成本决定这条线路能不能长期存在，共享出口的滥用与风控决定目标站点还认不认它，入口地址与协议特征决定链路会不会阻断它，订阅域名、DNS 与客户端配置决定它在你手里能不能被正确加载。看到“连接失败”时，先判断坏在哪一层，再决定等、换还是放弃。

## 1. 先把“失效”拆成四个问题

客户端弹出一个超时，只说明某一次请求没有走通。工程上要把可用性拆成四个问题，每个问题对应一条独立通道。

1. 订阅能不能拉取并解析。
2. 节点入口的 TCP 端口能不能握手。
3. 代理协议能不能完成认证。
4. 通过隧道能不能取回目标内容。

四条都通过，才有讨论速度和稳定性的必要。四条里任何一条失败，用户看到的现象都接近，这也是“节点坏了”这个说法流行的原因。把失效归因到某一个节点，通常会漏掉供给与链路两层，下一次还会在同一个地方卡住。服务成本决定供给能不能持续，限流决定高峰时还能不能用，连接稳定性则是这两项与本地条件共同作用的结果。

时间尺度也要分开。分钟级的失败常来自本地 DNS 缓存、客户端刚切换配置、系统时间偏差。小时级的失败常来自入口 IP 被封、端口限流、证书过期、目标站点风控。天到周尺度的失败常来自供给预算结束、订阅令牌吊销、出口 IP 信誉被耗尽。把时间尺度写进记录，能避免把一次晚高峰拥塞当成服务下线。

一次失败不构成结论。判定一个节点不可用，至少要有两个不同时间窗的失败记录，间隔不少于 30 分钟，目标、客户端与接入网络保持一致。两次都失败，再去看日志与证据。只失败一次就换节点，等于把线索丢掉。

本页解释机制与诊断顺序，不发布节点，不评价具体服务，也不提供绕过封锁的操作步骤。免费资源的收录状态见[免费机场](/free-airport/)，当前为 0 条，审核日期 2026-10-24，下次复核 2026-11-07。这个数字只表示本站没有可发布条目，不表示全网不存在免费服务。

本页适合已经拿到订阅、被反复失效困扰、准备判断“继续等还是换方案”的读者。只想找一条现在能用的节点的人，会失望。

## 2. 成本结构决定了免费线路的寿命

一条能对外提供服务的线路，月成本至少包含五块，出口带宽、入口与中转服务器、IP 地址、域名证书与面板、维护人力。用户数增加时，前四项都要加钱，人力也会从“顺手看看”变成值班。

带宽有两种常见计费方式。95 计费按一个计费周期内第 95 百分位的带宽峰值收费，短时突发会被削掉，持续高峰会进入账单。流量计费按实际传输的 GB 收费，每一个字节都对应成本。免费用户没有账单约束，用量会自然向高峰集中，这两种计费方式都会把峰值放大成现金支出。

IP 是第二块。IPv4 地址是稀缺资源，原生 IP、广播 IP、干净 IP 的获取难度不同。目标站点不只看 IP 归属地，还看 ASN 类型与历史滥用记录。一个地址被列入公开黑名单后，清洗需要时间，也需要成本。共享出口把这件事变成公共账户，谁都能透支，账单最后由所有用户一起承担。

域名、证书、订阅面板、监控与客服也要计入。证书到期没有续，订阅地址就会失效。面板被攻击，节点列表会泄露。没有监控，出口被打满也无人知道。这些项目的金额不大，却决定服务能不能被稳定维护。免费供给常常先砍掉这一块，故障因此更晚被发现。

把成本写成公式，能看清免费额度的上限。

```text
E_month = 324 × B × u          （GB/月，B 为 Mbps，u 为平均利用率）
c = C_month ÷ E_month          （元/GB）
S = Σ承诺峰值 ÷ B_port         （超售比，无量纲）
```

系数 324 来自一个月的秒数除以 8 与 1000。下面一组数字全部是测算假设，不是市场报价。假设出口端口 100 Mbps、月费 800 元，中转机 60 元，IP 与基础防护 100 元，月成本 960 元。平均利用率取 30%，可承载流量为 324 × 100 × 0.3，等于 9,720 GB。单位成本约 0.099 元/GB。

如果每个免费用户每月用 10 GB，972 个用户刚好覆盖这条线路的现金成本。用户涨到 5,000 人，需求变成 50 TB，按同样利用率需要约 514 Mbps 的端口，端口成本约 4,114 元，总成本约 4,274 元，收入仍然是零。免费额度越大，这个缺口越大。

供给方填缺口的方式只有四种，获客预算、捐赠、广告转化，或者把成本转给上游。预算停止，线路就消失。捐赠中断，公益节点就下线。广告转化不足，免费档会被收紧。上游被转发站消耗，转发站就会换源或直接停更。免费节点的寿命由现金流和维护意愿决定，技术优劣只能解释它坏得快不快。

## 3. 超售与限流把共享线路变成拥挤的出口

超售比是承诺峰值总和与物理端口带宽的比值。假设 3,000 个用户，每人承诺 50 Mbps 峰值，总和 150 Gbps，端口只有 1 Gbps，超售比 150:1。这个数字看起来夸张，实际系统靠所有人不会同时使用来运转。

峰值并发一上来，模型就失效。若 15% 的用户同时活跃，需求是 22.5 Gbps，端口只能给出 1 Gbps，平均每人 2.2 Mbps。若活跃比例升到 30%，平均每人 1.1 Mbps。网页还能打开，视频会开始缓冲，单线程下载会明显变慢。

排队会进一步放大问题。出口队列满后，往返时间上升，TCP 把丢包和延迟当成拥塞信号，降低发送速率，重传又增加流量。用户感觉是“越用越慢”，设备上的测速数字却可能仍然好看，因为测速常走多线程，短时间能把队列填满。

限流是另一层。免费档可能限制单用户带宽、并发连接数、UDP 转发或高峰时段用量。单用户 10 Mbps 的限额属于产品设计，不代表线路故障。判断时要看限制是否稳定复现，还是随时段波动。稳定复现的限额写在条款里，随时段波动的下降更可能来自拥塞。

限流可能发生在四个位置。本地路由器或安全软件、运营商接入、中转入口、落地出口。不同位置的证据不同。本地限速对所有节点生效，运营商限速常针对 UDP 或高位端口，入口限速对同一服务的所有用户生效，落地限速只影响特定目标。逐个替换变量，才能定位到位置。

缓冲区大小也会改变体感。缓冲区过大时，队列会先把延迟推高再丢包，用户感觉网页点不动，测速却仍有数字。缓冲区过小时，突发流量直接丢包，重传把有效带宽压低。两种配置都可能出现在共享出口上，单看平均速度无法区分。

几种现象可以区分拥塞与限流。晚高峰持续下降、凌晨恢复，指向出口拥塞。任何时段都卡在同一个数值，指向账户限速。前几秒很快、随后掉到很低，可能是突发额度用完。测速正常但网页首字节很慢，可能是排队延迟或目标站点响应慢，不一定是带宽不足。

## 4. 滥用把出口 IP 的信誉消耗掉

出口 IP 是目标站点在网络层看到的身份。一个免费节点可能同时承载网页浏览、视频、爬虫、批量注册、撞库尝试和自动化请求。目标站点无法区分这些行为来自哪个用户，只能给整个地址打标签。

标签的后果很具体。搜索会出现验证码，登录会要求二次验证，支付会被拒，流媒体会提示地区限制，AI 服务会限制会话。状态码常见 403 与 429，有时页面正常返回但功能被隐藏。这些现象与“节点断了”很像，实际链路仍然通。

ASN 类型会影响初始信任。机房地址在风控系统里的权重通常高于家庭宽带地址，共享地址池的历史记录又会叠加。一个地址被大量免费用户使用过，即使当前使用者规矩，也可能继承之前的标记。换 IP 能暂时缓解，新地址同样可能很快被消耗。

免费节点更容易遇到这件事，原因在公开性。订阅链接一旦被转发到公开页面，爬虫会在很短时间内抓取，随后进入各种聚合列表。用户规模在几个小时里扩大，滥用样本也跟着扩大。供给方如果没有能力做行为审计，只能看着出口信誉下降。

这里要区分两种“封”。入口被封指本地网络到节点地址的路径不通，表现为 TCP 超时或重置。出口被封指目标站点拒绝这个地址，表现为 403、429 或验证码。两者的处理方式相反，前者要换入口，后者要换出口或停止在该出口登录敏感账号。

判断出口状态时，至少用三个独立回显源比对 IP，再记录 ASN 与国家。三个来源一致，说明地址本身没有分歧；结果不一致，先怀疑地理数据库滞后。状态码与提示原文要一起保存，单写“打不开”无法区分目标侧拒绝与链路失败。

## 5. 入口封锁、协议指纹与传输限制

入口是节点地址与端口。入口失效时，订阅可能仍然能更新，节点列表也还在，只是所有连接都停在同一个位置。这个区别很重要，它把“订阅问题”和“入口问题”分开了。

先看一次连接经过哪些步骤。

```text
[客户端]
   │ ① 系统代理或 TUN 接管
   ▼
[本地内核] ──② 拉取订阅（HTTPS，独立通道）──▶ [订阅服务器]
   │
   │ ③ TCP 握手  SYN → SYN-ACK
   ▼
[入口 IP:端口] ──④ TLS 握手  ClientHello（含 SNI）──▶ [入口服务端]
   │                                                    │
   │ ⑤ 代理协议认证  UUID / 密码 / 传输字段             │
   ▼                                                    ▼
[隧道] ──⑥ 转发──▶ [中转] ──▶ [落地出口] ──⑦──▶ [目标站点]
                                      │
                                      └─ 出口 IP、ASN、地区策略
```

图中的 ③ 到 ⑦ 任何一处失败，客户端都可能只显示“连接失败”。把失败点标出来，才知道该看哪一段日志。

TCP 层的失败有两种常见形态。一种是超时，SYN 发出去没有回应，可能是地址不可达、端口被丢、路径被黑洞。另一种是重置，连接刚建立或刚发出数据就被 RST 打断，客户端报 connection reset。重置可能来自链路中间的设备，也可能来自本地防火墙或安全软件。换一个网络复测，能先排除本地因素。

重置至少有三个来源。本地防火墙或安全软件可能直接发 RST；家庭路由器或运营商 NAT 可能因会话表满而重置；链路中间的设备也可能在识别到特定流量后注入 RST。区分方法是换设备、换网络、换目标端口分别复测。三种来源的处理方式不同，只换节点通常无效。

TLS 层的失败更容易被误读。证书过期、域名不匹配、证书链缺失、系统时间偏差，都会让握手停在证书校验。链路中间设备也可能在 ClientHello 之后直接断开，客户端只看到 handshake failure。若客户端提示“关闭证书校验后可以连接”，正确动作是停止使用，关闭校验会给中间人替换证书留下机会。

证书链不完整时，桌面客户端可能正常，移动端却失败，因为两端信任库不同。这类失败在更换客户端后消失，容易被误判为节点恢复。记录时写清客户端与系统版本，才能区分是节点问题还是信任库问题。

协议指纹是另一类判断依据。TLS 握手里的版本、密码套件、扩展顺序、ALPN、SNI 写法，以及包长与时序，组合起来能形成可识别的特征。公开讨论里常提到 JA3 与 JA4，它们把 ClientHello 的字段组合成可比的指纹，便于横向对照，不能单独证明某个连接一定被识别。VMess 与 Shadowsocks 依赖自定义头部或随机化载荷，没有外层 TLS 时，可借用的证书与域名外观更少；Trojan 先完成 TLS，外观接近普通 HTTPS；VLESS 配合 REALITY 借用真实站点的证书链；Hysteria2 与 TUIC 走 QUIC，特征落在 UDP 上。

UDP 限制是免费节点的高频问题。部分网络对 UDP 限速、丢弃或只放行 443。QUIC 握手需要 UDP 往返，丢包时部分客户端会等待超时再回退 TCP，用户感觉是“卡了很久才连上”。语音、视频通话和基于 QUIC 的代理对这类限制最敏感。判断方法是分别测试 TCP 443 与 UDP 443 的握手，若 TCP 正常、UDP 持续失败，问题更可能在传输层限制。

MTU 问题常被忽略。以太网默认 1500 字节，PPPoE 常见 1492，IPv6 要求链路至少支持 1280。隧道会额外占用头部，WireGuard 在 IPv4 外层下约 60 字节。封装后若没有做 MSS 钳制，大包会被分片或丢弃。典型现象是网页能开、小请求正常、视频和大文件停在某个位置。路径 MTU 探测依赖 ICMP 反馈，部分网络屏蔽 ICMP，形成黑洞。客户端能否调整 MTU、是否启用 MSS 钳制，直接决定这类问题能否绕过。

## 6. 订阅、域名与更新制造的“假失效”

订阅与节点入口是两条独立通道。订阅服务器返回的是一份配置，节点入口负责转发流量。订阅域名被污染或封锁时，已经下载到本地的配置仍然可能工作，直到客户端重启或再次更新。节点入口被封时，订阅仍然可以更新，列表里只是多了一批连不上的地址。

一条订阅的生命周期通常包含生成、分发、拉取、解析、连接、失效六个阶段。生成与分发由服务方控制，拉取与解析由客户端完成，连接跨两端，失效可能发生在任何阶段。把阶段写进记录，比记“今天又不能用了”更容易找到规律。

订阅侧的失败有几类。域名解析被污染，客户端拿到错误地址或解析超时。令牌被吊销或过期，服务器返回 401 或 403。账户触发设备数限制，返回的列表被截断。请求带了不被识别的 User-Agent，服务器返回 HTML，客户端按 YAML 解析就会失败。转换服务停更，返回的配置语法过时。证书过期，HTTPS 拉取直接失败。

这些失败在客户端上的表现很统一，都是“更新失败”。排查要看三个东西，HTTP 状态码、响应内容类型、响应体的前几个字节。状态码 200 但内容是登录页，说明请求被门户或代理拦截。状态码 403 且内容是一段 JSON 错误，说明令牌或权限有问题。内容以 `<!DOCTYPE html>` 开头，说明拿到的不是订阅。

更新频率也会制造错觉。客户端默认可能每 24 小时拉取一次，手动更新才会立即生效。服务端换了入口，客户端还在用旧地址，用户以为节点失效。反过来，客户端刚更新完，缓存里的 DNS 记录还没过期，新地址解析不到，也会失败。把“最后一次成功更新时间”写进记录，能避免把旧配置当成新配置。

令牌要当密码管理。订阅链接被截图、转发或提交到公开仓库后，别人可以拉取节点、消耗额度，部分服务还能看到设备与连接记录。额度被耗尽后，节点不会立刻消失，表现为全部超时或认证失败。怀疑泄露时，先在服务端重置令牌，再检查流量与设备列表。

处理顺序可以固定下来。先确认订阅 URL 在当前网络能否打开，再确认返回内容能否解析，最后才看节点入口。顺序反过来，会在配置层反复导入，浪费大量时间。

## 7. DNS、客户端与本地网络

DNS 是独立于隧道的路径。查询可能走系统解析器、运营商递归、客户端内置解析器或加密解析器。污染的表现有三种，返回错误地址、返回 NXDOMAIN、查询超时。缓存会让问题延迟出现，域名已经换了地址，本地还在用旧记录，TTL 到期后才恢复。

判断 DNS 问题要对比三组结果。系统解析器的结果、加密解析器的结果、直接连接已知 IP 的结果。前两组不一致，问题更可能在解析路径。三组都失败，问题更可能在链路。只测一组，无法区分污染、缓存和节点故障。

客户端配置是另一层。系统代理只接管遵守系统设置的应用，TUN 通过虚拟网卡接管路由，覆盖更广，也需要更高权限。分流规则把目标域名设为直连，流量就不进隧道，用户看到的是“这个网站打不开”，其他网站正常。IPv6 是常见漏洞，客户端只代理 IPv4 时，双栈网络下的部分流量会走原生 IPv6，出口与预期不符。

同一份订阅在不同设备上表现不同，原因通常在这几项。客户端与内核版本不同，支持的协议字段不同。DNS 配置不同，一个用 fake-ip，一个用真实解析。系统时间偏差过大，依赖时间戳的认证会直接失败。防火墙或安全软件拦截了 TUN 网卡。设备启用了省电模式，后台连接被挂起。规则集没有更新，目标域名走了错误的分支。

系统时间偏差超过几分钟，依赖时间戳的认证会失败，证书校验也可能报“尚未生效”。开启自动同步，再复测一次，能排除一类低级故障。这个动作花不了一分钟，却经常被跳过。

本地网络也会制造“节点坏了”的错觉。公共 Wi-Fi 需要门户认证，未登录前所有请求都被重定向。家庭路由器的 MTU 设置异常，大包被丢。运营商在高峰时段对 UDP 限速。这些条件都能让同一条订阅在另一个网络里恢复正常。

可复现的记录比反复重装有用。记录订阅状态码、解析结果、入口握手耗时、TLS 握手结果、首字节时间与出口 IP。每次只改一个变量，改完立即复测。没有基线时，先测一次不走代理的直连结果，否则无法判断是本地带宽不足还是节点慢。

可以借助几条命令拿到原始字段。下面的地址与数值都是占位符，示例格式，非实测。

```bash
curl -x http://127.0.0.1:7890 -sS -o /dev/null \
  -w 'code=%{http_code} dns=%{time_namelookup} tcp=%{time_connect} tls=%{time_appconnect} ttfb=%{time_starttransfer}\n' \
  https://example.com/
```

`time_connect` 接近 TCP 握手，`time_appconnect` 包含 TLS，`time_starttransfer` 是首字节。三个数一起看，能判断慢在握手还是目标响应。命令只演示字段，执行前要替换示例域名，并确认目标服务允许此类请求。

| 观测项 | 单位 | 观测方法 | 采样口径（示例） | 判定参考（示例） | 数据性质与限制 |

## 9. 六类失效模式对照

把前面的机制收拢成六类，排查时先归类，再找证据。六类可能同时出现，例如成本收紧导致超售加剧，超售又放大滥用带来的风控。六类可以归回成本、出口、链路与本地四层，分类只服务于排查顺序。分类的作用是决定先修哪一层，不承诺一次修好。

| 失效类型 | 触发条件 | 用户看到的现象 | 可查证据 | 典型时间尺度 | 处理方向 |
| --- | --- | --- | --- | --- | --- |
| 成本与供给退出 | 预算停止、捐赠中断、广告转化不足 | 整条订阅长期不更新，公告停更 | 官方页面停更、域名到期、节点列表不再变化 | 周到月 | 放弃，启用备用方案 |
| 超售与限流 | 峰值并发超过出口容量，免费档被限速 | 晚高峰变慢，视频卡，测速数字尚可 | 分时吞吐对比、丢包与重传计数 | 小时到天 | 换时段或换线路 |
| 滥用与出口风控 | 共享 IP 被用于批量注册、抓取、撞库 | 403、429、验证码、登录失败 | 状态码、提示原文、出口 IP 信誉 | 小时到天 | 换出口，隔离账号 |
| 入口 IP 与端口封锁 | 入口地址公开、被扫描、被举报 | TCP 超时或重置，订阅仍可更新 | tcping 结果、路由、握手阶段 | 分钟到小时 | 等更新或换入口 |
| 协议指纹与传输限制 | 特征被识别，UDP 被限速，MTU 黑洞 | TLS 握手失败、QUIC 不通、大包卡住 | 握手日志、UDP 探测、MTU 探测 | 分钟到天 | 换传输或调整 MTU |
| 订阅、DNS 与本地配置 | 域名被污染、令牌吊销、客户端错配 | 订阅打不开、解析错误、全部超时 | 解析对比、订阅状态码、客户端日志 | 分钟到天 | 按层修配置 |

表注：时间尺度指从触发到用户可感知的常见范围，属于经验区间，不构成承诺。处理方向只列方向，具体动作要看客户端能力与服务条款。六类之间没有排他关系，同一时刻可能有两类同时成立。

## 10. 分层诊断流程

诊断顺序从本地到远端，从配置到链路。顺序固定的好处是每一步都能留下证据，避免在同一层反复换节点。

```text
起点：订阅里的节点全部或部分不可用
│
├─ 第 1 层  订阅层
│  ├─ 订阅 URL 打不开
│  │  ├─ 换网络仍失败 → 域名、令牌或服务端问题，记录状态码后停止重试
│  │  └─ 换网络能打开 → 本地 DNS 或路径问题，修解析后重试
│  └─ 订阅能打开但为空或解析失败 → 格式、令牌或客户端版本
│
├─ 第 2 层  入口层
│  ├─ 入口 TCP 不可达 → IP、端口或本地防火墙，换探测点复测
│  └─ 入口 TCP 可达
│     ├─ TLS 握手失败 → 证书、SNI、时间或中间设备
│     └─ TLS 握手成功 → 进入第 3 层
│
└─ 第 3 层  隧道与目标层
   ├─ 代理认证失败 → 密码、UUID、时间偏差、协议版本
   ├─ 认证成功但目标返回 403 或 429 → 出口信誉或目标地区策略
   ├─ 小请求成功、大流量停住 → MTU、UDP 限速或拥塞
   └─ 全部通过但时快时慢 → 超售、峰值拥塞或本地带宽
```

每层设一个超时。TCP 握手 3 秒，TLS 握手 5 秒，首字节 10 秒。超时就记录当前结果，进入下一层，不无限等待。等待时间过长会让记录失去可比性，也会把一次临时拥塞放大成“彻底坏了”。

每层只改一个变量。换节点的同时换客户端版本，结果无法归因。固定客户端与配置，只切换节点，连续测三轮，才能看出差异。需要换客户端时，先保留旧配置与旧日志，再对比新结果。

失败也要记录。超时值、状态码、错误行数都是证据。只写“失败”两个字，下一次就没有比较基准。两个时间窗都失败，才把节点标记为不可用。中间恢复过一次，记录恢复时间与恢复后的表现，这比“时好时坏”有用。

三层都通过但仍然不稳定，问题落在容量与目标侧。回到第 3 节与第 4 节，按时段记录吞吐与状态码。若晚高峰持续下降，优先怀疑超售。若任何时段都遇到 403 与验证码，优先怀疑出口信誉。这两类问题换客户端解决不了。完整的逐层排查动作见[免费机场无法使用时怎么办](/guides/free-airport-not-working)。

用两个示例走一遍。示例一，订阅能更新，入口 TCP 连续 20 次全部超时，TLS 没有开始，换一个网络仍然超时。结论落在入口层，动作是等待服务端换入口或启用备用节点，继续重装客户端没有意义。示例二，入口 TCP 与 TLS 都成功，代理认证连续失败，系统时间比标准时间慢 8 分钟。结论落在配置层，动作是校准时间并核对 UUID 或密码，换节点不会解决问题。两段均为示例数据，非实测，不对应任何真实服务。

## 11. 什么时候应该停止修复

修复也有成本。一次修复包含发现、定位、切换、验证四段，通常不止点击一次。把时间折成钱，才能判断继续修是否划算。

```text
T_month = n × t × w

n  每月失效次数      t  单次修复小时数      w  时间价值（元/小时）
```

假设每月失效 8 次，每次 15 分钟，时间价值按 40 元/小时的测算假设计算，月时间成本为 8 × 0.25 × 40，等于 80 元。这个数字还没有算上中断造成的损失与情绪消耗。测算假设只用于演示算法，不代表任何人的真实收入。若一个低价档的月费在 10 元到 20 元之间，时间成本已经超过现金支出。

退出条件要在开始使用前写下来。连续 3 天、每天至少 2 次失败，每次修复超过 15 分钟，就启用备用方案。需要关闭证书校验才能连接，立即停止。要求提交身份证、人脸或他人账号，立即停止。条款新增自动续费或扣费，先取消再判断是否继续。

免费额度适合做一次有期限的验收，不适合放进长期生产。验收要回答四个问题，额度多少、期限多久、达标标准是什么、退出路径在哪。把答案写成一页记录，再决定是否把它当主力。具体流程见[免费机场试用怎么判断是否真实可用](/guides/trial-verification)。

替代方案不必立刻升级到高价档。先算自己的月用量与峰值需求，再看小流量套餐、月付与流量包的单位成本。月用量只有几 GB 时，流量包可能更合适。需要长期在线时，可追责的恢复时间比标价更重要。

挑替代方案先看三件事。能不能按月退出，额度口径是否写得清楚，故障时有没有可联系的渠道。三项都模糊时，低价也只是把维护成本换了一个位置。

## 12. 怎样证明一个节点真的失效

证明失效需要两次失败记录与一份环境说明。环境说明包含接入方式、签约带宽、设备、系统、客户端与内核版本、代理模式、DNS 配置。缺少任何一项，别人无法复现你的结论。

记录字段可以固定为八项。时间与时区、节点标识、协议与传输、客户端与内核、探测方式、目标端点、结果与单位、证据文件名。节点标识用地区加序号，不写服务商名称，避免把记录写成推荐。

日志要保留原始行。下面四行只演示字段长什么样，节点名与地址都是占位符，示例格式，非实测。

```text
2026-10-24 21:05:12 [TCP] dial example.com:443 via entry-a:443  error: i/o timeout
2026-10-24 21:06:03 [TLS] handshake failed  remote error: tls: handshake failure
2026-10-24 21:07:44 [UDP] QUIC handshake timeout  fallback: tcp
2026-10-24 21:09:10 [DNS] lookup example.com: server misbehaving
```

四行分别指向入口不可达、TLS 层失败、UDP 受限与解析异常。它们只是字段示例，不能当成对任何服务的诊断结论。真实日志的格式随客户端与内核版本变化，阅读时以官方文档为准。

证据分等级。原始命令输出加时间戳，可以重放，属于高强度证据。截图带系统时间与参数，属于辅助证据。只有一句“连不上”，只能当线索。转述他人的结果，无法追溯，不采用。同一结论在两个时间窗复现，才写入正式结论。方法与口径统一指向[资源检测方法](/resource-check/#method)。

## 13. 安全、隐私与合规边界

代理改变出口 IP，不改变账号、支付信息、设备指纹与行为轨迹。HTTPS 保护内容，默认配置下不隐藏你访问了哪个域名，也不隐藏访问时间。把免费节点当成匿名工具，会高估它的能力。

证书校验不能关闭。客户端提示证书错误时，正确动作是核对域名、有效期与签发者，或者停止使用。关闭校验会让链路上的中间人更容易替换证书并读取内容。免费服务出现这类提示时，提示本身就是风险信号。

订阅链接要当密码。不截图、不转发、不提交到公开仓库。怀疑泄露时先重置令牌，再检查流量与设备列表。测试账号与日常账号分开，不在来源不明的出口登录主邮箱、网盘与支付账户。

不同司法辖区对代理工具、加密服务与跨境访问的规则不同。使用前需要自行确认当地法律、服务条款与可接受使用政策。本页不提供规避执法、规避实名制或绕过服务地区限制的操作方法。

## 14. 常见问题

### 免费节点失效是不是因为用的人太多？

用的人多会放大问题，原因不止一个。共享出口的带宽、IP 信誉、维护预算都会随用户数变化。用户增加会先表现为晚高峰变慢，随后目标站点开始给出口打标签，最后供给方因成本收紧额度或停止更新。判断时要看失效是否集中在高峰、是否伴随 403 与验证码、订阅是否还在更新。三层证据分开记录，下一次就知道该等、该换还是该放弃。

### 为什么同一订阅在手机上能用，电脑上不能用？

先比较两端的客户端与内核版本、代理模式、DNS 配置和系统时间。手机可能走 TUN 并启用了 fake-ip，电脑只用系统代理，某些应用不遵守系统设置，流量根本没进隧道。电脑的防火墙或安全软件也可能拦截 TUN 网卡。另一个常见差异是 IPv6，手机走 IPv4，电脑优先走 IPv6，出口与预期不一致。若只有一个应用失败，再查它是否绕过系统代理或自带 DNS。逐项对齐后再判断节点。

### 客户端显示超时，换个节点就好了，说明什么？

说明原节点的入口或认证在那次请求里失败了，新节点只是绕开了故障点。它不能说明原节点永久失效，也不能说明新节点稳定。正确做法是回到原节点，在两个时间窗复测，记录 TCP 握手、TLS 握手与认证结果。若两次都失败，再标记不可用。频繁换节点会把不同层的故障混在一起，最后只剩下“时好时坏”的印象。新节点也可能在几小时后失效。

### 免费节点白天能用晚上不能用，算限速吗？

可能是限速，也可能是拥塞。账户限速通常在任何时段都卡在同一个数值，拥塞则随在线人数变化，晚高峰下降、凌晨恢复。记录同一目标在 14 时与 21 时的单线程吞吐、丢包与首字节，连续三天。若白天正常、晚上持续下降，优先怀疑出口超售。若白天也卡在同一上限，查条款里的免费档限额。拥塞只能避开高峰或换线路，限速则可以先对照条款确认额度。

### 订阅链接打得开，节点却全部超时，问题在哪？

订阅与节点入口是两条通道。订阅能打开，说明域名、令牌与客户端解析基本正常。节点全部超时，问题更可能在入口 IP、端口、本地防火墙或运营商路径。先对入口做 TCP 握手，再看 TLS 握手，最后看认证。若入口可达而认证失败，回到配置与时间同步。不要因为订阅正常就排除本地网络。同一订阅在另一台设备也全部超时，入口问题的概率更高。

### TLS 握手失败和密码错误怎么区分？

看失败发生在哪一步。TLS 握手失败时，客户端通常在证书校验或 ClientHello 之后报错，日志里出现 handshake failure、证书过期或域名不匹配。密码错误发生在 TLS 之后的代理认证阶段，日志里是认证失败或鉴权错误。若客户端先提示证书问题，再提示认证失败，先处理证书与时间，再核对密码。两步的日志阶段不同，分开记录就能区分。两个问题可能同时存在，先修前一层。

### UDP 被限制会有什么表现？

QUIC 握手超时，部分客户端等几秒后回退 TCP，用户感觉是连接很慢。语音、视频通话和基于 QUIC 的代理会断续或直接失败。网页与下载可能正常，因为走了 TCP。判断时分别测试 TCP 443 与 UDP 443，记录握手成功率和等待时间。若 TCP 正常、UDP 持续失败，问题更可能在网络对 UDP 的处理，换协议比换节点更有效。有些网络只限制大流量 UDP，握手能过、传输会断，测试时要传一段持续数据。

### DNS 污染和节点失效怎么区分？

对比三组解析结果。系统解析器、加密解析器、直接连接已知 IP。前两组不一致，问题更可能在解析路径。三组都失败，问题更可能在链路。DNS 污染的典型表现是返回错误地址、NXDOMAIN 或超时，换一个解析器就能恢复。节点失效时，解析可能完全正常，只是入口连不上。先看解析，再看握手，顺序不要颠倒。更换解析器后恢复，基本可以归到解析层。

### 免费节点需要每天更新订阅吗？

按客户端的更新间隔与服务端的变更频率决定，不必机械地每天手动点。多数客户端默认 24 小时拉取一次，服务端换入口时可以在客户端手动更新。更新前导出一份旧配置，更新后对比节点数量与入口地址。若更新后全部失败，先回滚旧配置，再确认订阅内容是否被替换。频繁更新不会让坏节点变好，只会增加变量。把更新前后的节点数量记下来，比凭印象判断可靠。

### 节点被封锁后等几天会恢复吗？

可能恢复，也可能永久消失。入口 IP 被临时阻断时，供给方换地址或换端口后会恢复。地址被长期标记、服务端停止维护、预算结束时，等待没有意义。判断依据是订阅是否继续更新、官方页面是否还在维护、同一条订阅的其他入口是否可用。连续一周没有更新，且多个入口都失败，应当按供给退出处理，准备替代方案。等待期间保留旧配置与失败记录，恢复后才有对照。

### 免费节点能不能登录重要账号？

不建议。免费节点的出口由他人控制，运营方可以看到连接时间、目标域名与流量体积。共享出口还可能被用于滥用，导致目标站点要求验证码或二次验证。登录主邮箱、网盘、支付账户会把账号与一个不可控的出口关联起来。需要登录时，使用独立账号与独立浏览器配置，完成操作后退出并清理缓存。若必须登录，先确认条款允许，并准备随时撤销会话。代理不承诺匿名。

### 什么时候应该停止修节点，改用低价方案？

当修复成本超过替代成本时。连续 3 天、每天至少 2 次失败，每次修复超过 15 分钟，就可以停止。按每月 8 次、每次 15 分钟、时间价值 40 元/小时计算，月时间成本约 80 元，已经高于 10 元到 20 元档的月费。这个算例是测算假设，判断逻辑通用。先写退出条件，再执行，避免在失效当天反复重装。把每次修复的起止时间记下来，一周后回看，判断会比当天准。
