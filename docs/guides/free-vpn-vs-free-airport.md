# 免费梯子和免费机场有什么区别？新手应该先了解哪些限制

> 免费梯子是一个组合，包含客户端软件、协议实现、节点参数与服务供给四层，免费机场只对应最后一层。机场指运营方把节点打包成订阅发放，可能免费、可能限时试用、也可能按套餐收费。区别的核心落在谁支付服务器与带宽的账单。客户端可以永久免费下载，服务器不行，它按流量和峰值计费。新手先确认这笔账单的承担者，再谈额度与速度。

## 两个词不在同一层

### 梯子是一个组合

中文互联网把能把请求送到境外出口的东西统称为梯子，这个叫法把四层结构压成了一个词。第一层是客户端，负责界面、规则、系统代理或 TUN 接管，决定哪些流量走代理、哪些直连。第二层是协议，约定两端怎么封装、怎么认证、能不能伪装成普通的 HTTPS 流量。第三层是节点，一组地址、端口、密钥与传输参数，写在订阅文件或分享链接里。第四层是服务供给，也就是谁维护服务器、谁付带宽、谁处理封禁、出了问题找谁。

四层的成本结构完全不同。客户端与协议来自开源项目，代码可以无限复制，边际成本接近零。节点是一段配置文本，复制不花钱。服务器与带宽按月和按 GB 计费，用的人越多账单越高。把四层混成一句“免费梯子”，等于把可以免费的部分和不能免费的部分绑在一起谈，讨论很难落地。

四层还可以来自四个互不相干的地方。客户端从官方仓库下载，节点从朋友那里拿到，服务器由陌生运营方维护，四者之间没有合同关系，任何一层出问题，其他三层都不会通知你。

### 机场是供给层的一种形态

机场是中文社区对订阅制代理服务的称呼，与航空运输无关。一个运营方采购或租用服务器，部署协议，把节点整理成订阅地址，按额度、期限与设备数发给用户。同一个运营方可以同时发免费额度、限时试用和付费套餐，三者共用一套面板、一套节点、一套客服。所以机场描述的是一种发放方式，不构成一类技术，也不构成一家厂商。

把机场放回四层里看，它只覆盖最后一层，另外顺带影响第二层和第三层的具体取值。协议由运营方选定，节点由运营方维护，客户端通常留给用户自选。这也是为什么同一个机场的订阅能同时导入多个客户端，而换一个机场往往只要换一条订阅地址。

层级关系可以写成一句包含关系。免费机场是免费梯子的一种供给形态，免费梯子还可能来自自建服务器、公开分享的单节点、公司内网出口、商业 VPN 的免费档。把两者当成并列的两个东西比较，会得出“机场比梯子好用”这类没法验证的结论，因为被比较的对象不在同一层。

### 三种常见的混用

第一种混用把客户端当成服务。Mihomo、Xray-core、sing-box 这类项目发布的是软件，装在本地，跑在用户自己的设备上。它们的仓库里没有节点，官网也不承诺任何线路。下载页面能打开，只说明软件可用，与能不能连出去无关。

第二种混用把节点当成机场。一个 IP 加一个端口加一串参数就能构成节点。朋友发你一条、公开列表里抄一条，都算节点。机场的特征是有运营方、有订阅地址、有额度说明、有条款。只有节点没有主体，出问题时找不到人，也找不到可以引用的规则。

第三种混用把试用当成免费。试用有起算点、有期限、有额度上限，到期后要么停，要么转成付费。把试用当免费，最常见的后果是到期那天刚好有急事。判断方法很简单，看领取页面有没有写“到期后自动转为付费”或者“需绑定支付方式”。

### 层级错位会问错问题

新手最常问的是“免费梯子和免费机场哪个快”。这个问题把整体和其中一层放在一起比，答案取决于你手上恰好有什么，没法推广。换成“我缺的是软件、服务器，还是线路质量”，问题立刻可以回答。缺软件就去官方仓库下载，缺服务器就进入成本判断，缺线路质量则要换供给方。

层级错位还会带来一种误判，把软件更新当成线路改善。客户端升级到新版本，节点还是原来那一批，出口地址、带宽与封锁状态都没有变，感觉变快多半来自规则调整减少了绕行，或者恰好错开高峰。

## 成本落在谁身上

### 服务器账单由哪些项组成

一条线路的月账单至少有六项。入口服务器的租用费按 CPU、内存与系统盘计价，通常固定。出口带宽按计费流量或 95 峰值计费，是账单里波动最大的一项。IP 资源包括额外地址的月租与更换 IP 的时间成本。域名与证书，证书本身可以免费申请，域名注册与自动续期要占一份运维。面板与订阅分发，用户量上来之后需要数据库、任务队列与 CDN。人力，处理封禁、工单、投诉与退款。

六项里只有第一项和第五项能靠技术手段压到很低。带宽单价由机房与线路决定，跨境方向的成本高于本地互联，这是物理距离和互联结算共同决定的。IP 被目标站点批量标记之后，换地址要重新积累信誉，这段时间里的体验是下降的。所以免费方案省下来的通常不是成本，只是把成本记在了别人账上。

### 客户端免费与服务免费的分界

开源客户端的边际成本接近零。一份代码复制一千万次，服务器账单不会因此增加一分钱。这类项目可以长期免费，靠的是维护者的时间与社区的补丁。服务器的边际成本随用量上升，一个用户多看一小时视频，出口就多跑一到三 GB 流量，具体取决于码率。两类成本的曲线形状不同，软件免费推不出服务免费。

日常讨论里常见的推理错误有三步。看到客户端开源，认为软件免费。看到软件免费，认为整条链路免费。看到有人在用，认为可以长期免费用。三步里每一步都需要额外证据，缺一步结论就不成立。判断时把问题换成“这台服务器这个月的账单谁付”，答案会清楚很多。

### 免费能撑多久

判断一条免费供给的寿命，看三个量。转移源是否稳定，出钱的一方有没有持续动机。容量是否够分，免费额度通常不限人数，人一多单位成本就上升。维护是否有主，出现封禁和故障时有没有人处理。三个量里任意一个归零，供给会在几周内消失。这也解释了为什么免费方案经常在“刚被推荐完”之后失效，推荐带来流量，流量抬高成本，成本超过转移源的承受能力。

## 订阅与额度

### 订阅是一条带令牌的通道

订阅地址是一串带令牌的 URL，客户端定时用 HTTPS 拉取，服务端按令牌返回节点列表或完整配置。令牌等同于账号凭证，拿到它的人可以拉配置、消耗额度、看到你的出口地址。同一个 URL 在不同 User-Agent 下可能返回不同格式，Clash YAML、sing-box JSON、Base64 链接列表各有一套字段，所以同一条订阅在两个客户端里表现不同属于正常现象。

订阅通常经 CDN 分发，响应头里的缓存策略会让更新延迟。手动点过更新之后仍然是旧节点，先看响应头与本地配置文件的时间戳，再看服务端。反过来，令牌被吊销时拉取会返回错误或空列表，部分客户端会保留旧配置继续用，于是出现订阅已经失效但连接还能维持的状态。

### 额度四要素

| 要素 | 常见写法 | 需要追问的口径 | 缺失时的后果 |
| --- | --- | --- | --- |
| 量 | 每月 100 GB | 十进制还是二进制，上下行是否合计，是否按倍率扣减 | 无法估算可用时长 |
| 期 | 30 天 | 从注册、首次连接还是付款起算，按自然月还是滚动 30 天 | 不知道哪天停 |
| 设备 | 3 台 | 同时在线 IP 数还是累计登录设备数，是否绑定设备指纹 | 家庭共享时超限 |
| 速率 | 不限速 | 单连接上限还是账号合计上限，高峰是否动态调整 | 视频码率选错 |

量、期、设备、速率四项同时写清，额度才可复核。免费机场的说明经常只写第一项，写“送 100G”而不写期限与重置规则。这种写法没法验证，只能当成线索。自己列一张四行的表，四项都有答案再进入下一步，缺项就按最坏情况估算。

### 免费额度常见的四种形态

一次性流量用完即止，适合旅行与应急。按日重置的小额度每天几百 MB 到几 GB，能浏览不能看视频。限时不限量在三到七天内不扣流量，通常伴随限速。限速不限量把速度压到几百 Kbps，网页能开，高清视频打不开。四种形态对场景的适配完全不同，看到“免费”两个字先问属于哪一种。

运营方还会在活动期给限时不限量，活动结束后改成按日小额度，用户的感受是“突然变慢变少”。条款里如果没有写形态的稳定期，这种变化随时可以发生。

| 比较维度 | 免费梯子（自备客户端加节点） | 免费机场（运营方发订阅） | 商业 VPN 免费档 | 判断口径 | 数据性质 |
| --- | --- | --- | --- | --- | --- |
| 交付物 | 安装包与一组节点参数 | 一条订阅地址，客户端自选 | 一个打包好的应用 | 拿到手的是什么 | 结构描述 |
| 服务器出资方 | 你自己，或节点提供者 | 运营方 | 厂商 | 谁在付月账单 | 结构描述 |
| 客户端控制权 | 完全在本地，内核与规则可选 | 客户端自选，规则受订阅影响 | 厂商控制，可调项很少 | 能不能换内核 | 结构描述 |

| 典型失效 | 地址被封、证书过期 | 令牌吊销、停更、额度耗尽 | 免费档缩水、地区限制 | 失效时看到什么 | 结构描述 |

| 迁移成本 | 换服务器要重配 | 换机场要重新导入 | 换厂商要重装 | 换方案要多久 | 结构描述 |

三列里最容易看错的是客户端控制权。机场给的订阅可以决定规则集、DNS 策略甚至回落行为，客户端虽然装在你机器上，实际路由未必由你决定。自备方案里这些内容都在本地配置文件里，改一行就生效。商业 VPN 的免费档相反，客户端与服务器一起被厂商控制，用户能调的只有开关。

支持渠道同样容易高估。自备方案没有客服，出事只能自己查日志。机场的免费额度排在付费用户之后，工单排队时间不承诺。商业 VPN 有客服入口，免费档的优先级同样靠后。三种情况指向同一件事，免费方案在故障时刻的救援能力最弱，而故障恰恰是它最容易发生的时候。

## 决策树：先确认你缺哪一层

下面的树按“缺什么”分流，第四层是所有分支共用的退出条件。每层只问一个能用是否回答的问题，避免“看情况”这种没法执行的判断。

```text
│   │   └─ 第 2 层  订阅来源能否追溯到运营主体
│   │       ├─ 能 → 第 3 层  额度四要素是否写在同一页
│   │       │        ├─ 是 → 结论 A  按订阅使用，先做两周记录
│   │       │        └─ 否 → 结论 B  只当临时线索，不写入主力配置
│   │       └─ 不能 → 结论 C  换开源客户端并自备服务器，或放弃
│   └─ 缺服务器（只有软件）
│       └─ 第 2 层  是否愿意承担每月固定支出与维护
│           ├─ 愿意 → 第 3 层  能否自己处理证书、端口与封禁
│           │            ├─ 能 → 结论 D  自建，成本可算，责任自负
│           │            └─ 不能 → 结论 E  订阅制付费档，买运维
│           └─ 不愿意
│               └─ 第 3 层  使用期限
│                   ├─ 一周以内 → 结论 F  试用或临时方案，先写退出条件
│                   └─ 一个月以上 → 结论 G  免费方案不成立，回到预算
│
└─ 第 4 层  所有分支共用，写下切换与退出规则
    ├─ 备用线路是什么，放在哪里
    ├─ 触发切换的条件，例如连续 6 小时不可用
    └─ 退出时要删除的凭据，订阅令牌、客户端配置、支付授权
```

走这棵树时注意结论 B 的处理方式。来源不明的订阅可以打开，但不进入主力配置。把它放在单独的客户端配置里，规则只覆盖少数测试域名，出问题时不影响正常工作流。这个做法不提高可用性，只降低故障的连带损失。

结论 D 与 E 的分岔点不在钱，在手上有多少时间。自建要求能读日志、能判断证书链、能在地址被封后换入口，这些技能的学习成本通常高于一年的订阅费用。愿意承担维护的人适合自建，不愿意的人适合订阅，买到的正是别人已经付出的运维时间。

## 一条连接里的两个平面

把订阅和数据分开看，两类方案的差异会清楚很多。订阅走控制面，低频，几分钟到几小时一次，HTTPS 拉取，体积几 KB 到几百 KB。数据走数据面，高频，每条连接都要经过，体积按 GB 计。两条通道的失效方式不同，混在一起排查会得出错误结论。

```text
控制面（低频，分钟到小时级）
  客户端 ──HTTPS GET 订阅地址，携带令牌──▶ 订阅服务器或 CDN
         ◀── YAML / JSON / Base64 节点列表──
         └─ 解析字段 → 写入本地配置 → 加载规则集

数据面（高频，每连接一次）
  应用 ──本地回环 SOCKS5 或 HTTP CONNECT──▶ 内核
        └─ 按规则选择 direct / proxy / reject
              └─ 隧道封装 ──▶ 入口服务器 ──▶ 中转 ──▶ 落地出口 ──▶ 目标站点
                                                        │
                                                  SNI 可见、段口与时段可观察
```

### 控制面负责“有哪些节点”

控制面暴露的是供给方的配置能力。订阅返回几个节点、叫什么名字、走哪种协议、带不带规则集，全部由服务端决定。控制面失效的表现是列表拉不下来、拉下来是空的、拉下来还是昨天的内容。它不影响已经在内存里运行的配置，所以经常出现控制面已经坏掉、数据面还能撑一段时间的状态。

### 数据面负责“字节怎么出去”

数据面暴露的是链路质量与封锁状态。握手能不能完成、出口 IP 有没有被标记、UDP 通不通、带宽够不够，都在这一层体现。数据面失效的表现是转圈、超时、能连上但打不开网页。它与订阅是否最新没有必然关系。排查顺序是先看拉取记录，再看握手，最后看目标站点返回的状态码，三步做完再决定要不要换订阅。

## 成本公式与两组测算

### 公式

```text
现金成本      P = 套餐价格，单位元
时间成本      T = n × t × w
可用流量      E = Q ÷ m × (1 - l)
单位成本      c = P ÷ E
总拥有成本    C = P + T + R
自建月成本    C_self = S + D ÷ 12 + h × w
```

变量含义如下。n 是每月失效次数，t 是单次修复耗时，单位小时，w 是本人的时间价值，单位元每小时。Q 是计费额度，单位 GB，m 是平均倍率，l 是链路损耗率，包括重传、握手失败与测速浪费。R 是风险折算，含隐私、账号与支付风险，单位元每月。S 是服务器月租，D 是域名与证书的年费，h 是每月维护小时数。

### 假设表

| 参数 | 符号 | 取值 | 单位 | 性质 |
| --- | --- | --- | --- | --- |
| 时间价值 | w | 40 | 元/小时 | 测算假设 |
| 每月失效次数 | n | 4.33 | 次/月 | 测算假设，约每周 1 次 |
| 单次修复耗时 | t | 0.33 | 小时/次 | 测算假设，约 20 分钟 |
| 计费额度 | Q | 43 | GB/月 | 测算假设，按每 7 天 10 GB 折算 |
| 平均倍率 | m | 1.5 | 倍 | 测算假设 |
| 链路损耗率 | l | 8% | 无量纲 | 测算假设 |
| 服务器月租 | S | 35 | 元/月 | 测算假设 |
| 年度域名支出 | D | 60 | 元/年 | 测算假设 |

### 测算一，免费额度的实际单价

假设某免费额度每 7 天重置 10 GB，一个月按 4.33 周计，标称约 43 GB。倍率 1.5，损耗 8%，可用流量 E 等于 43 除以 1.5 再乘 0.92，约 26.4 GB。每周失效一次，每次 20 分钟，月时间成本 T 等于 4.33 乘 0.33 再乘 40，约 57.2 元。现金支出为零，总成本就是 57.2 元，摊到 26.4 GB，单位成本约 2.17 元每 GB。

对照一条测算假设里的订阅，月付 10 元、计费 100 GB、倍率 1.0、损耗 8%，可用流量 92 GB，单位成本约 0.109 元每 GB。两者相差二十倍。倍数之外还有一层，免费方案省下的现金上限只有 10 元，时间成本却是它的五倍多。现金账上省钱，总成本账上可能更贵。

风险折算 R 还没有计入。免费额度通常要求邮箱或手机号注册，这部分成本无法用统一价格衡量。把 R 当成零会让免费方案显得更划算，把 R 当成正数则需要写出依据，两边都要交代。

### 测算二，自建与订阅的临界点

假设一台服务器 35 元每月，包含 500 GB 流量，域名 60 元每年折 5 元每月，每月维护 2 小时，时间价值 40 元每小时，维护成本 80 元。自建月成本为 35 加 5 加 80，等于 120 元。

按不同月用量摊开。月用量 100 GB 时，单位成本 1.20 元每 GB。月用量 500 GB 时，单位成本 0.24 元每 GB。要追平订阅方案的 0.109 元每 GB，月用量需要达到约 1,100 GB，而这条假设里的流量额度只有 500 GB，超过之后要另买带宽，单价还会上升。在这个假设下，自建在单位成本上赢不了低预算订阅。

换一个时间价值就能看到翻转。把 w 降到 10 元每小时，维护成本变成 20 元，自建月成本 60 元，按 500 GB 摊开是 0.12 元每 GB，与订阅基本持平。也就是说，自建是否划算，主要由你自己的时间价格决定，服务器价格只是其中一个变量。

### 临界点怎么读

两个测算都指向同一个结论。免费与自建的比较对象应当是总成本，现金只是其中一项。免费方案能省下的现金不会超过订阅价格，省不下的时间却可能达到订阅价格的数倍。

公式里最敏感的两个量是失效次数和单次耗时。它们由你的熟练度、客户端是否预配置、有没有备用线路共同决定。熟练的人修一次五分钟，不熟练的人修一次一小时，同样一条免费线路，总成本可以差十二倍。这也是为什么别人的“能用”体验无法直接搬到自己身上。

## 失效方式不一样，责任方也不一样

免费方案失效时，用户看到的都是“连不上”。拆到层，责任方完全不同。下表把十种常见失效按层排开，列出两种方案下的表现、可观察证据与处理顺序。

| 失效层 | 自备方案的表现 | 订阅方案的表现 | 可观察证据 | 责任方 | 处理顺序 |
| --- | --- | --- | --- | --- | --- |
| 客户端与内核版本 | 升级后配置语法不兼容 | 订阅字段新内核不识别 | 启动日志报配置错误 | 你自己 | 回滚版本或改配置 |
| 协议参数与系统时间 | 时间漂移导致认证失败 | 同左，令牌与时间都可能出错 | 握手在认证阶段中断 | 你自己 | 校准系统时间 |
| 入口地址与端口 | 地址被封，端口不通 | 一批节点同时超时 | TCP 连接超时 | 运营方或你 | 换地址或换入口 |
| 证书与域名 | 证书过期，续期失败 | 证书链异常，域名不匹配 | 客户端报证书错误 | 你自己或运营方 | 核对有效期与签发者 |
| 订阅令牌 | 不存在这一层 | 拉取返回错误或空列表 | HTTP 状态码、响应体 | 运营方 | 重置令牌 |
| 出口 IP 信誉 | 出口被目标站点标记 | 共享出口被标记的概率更高 | 验证码、状态码异常 | 运营方或你 | 换出口 |
| 额度耗尽 | 云账单超额或停机 | 面板显示额度用尽 | 面板读数、限速表现 | 你自己或运营方 | 加额度或等重置 |
| 供给方停服 | 不存在这一层 | 域名失联，公告消失 | 官方页面无法打开 | 运营方 | 启用备用方案 |
| 本地网络限制 UDP | QUIC 类协议直接不可用 | 同左，UDP 节点全部失效 | 握手无响应，TCP 正常 | 你的网络 | 改用 TCP 类协议 |
| 目标站点风控 | 出口段被整体限制 | 同左，共享段更明显 | 页面提示地区或异常 | 目标站点 | 换出口或放弃该站点 |

表注：本表只描述失效位置与责任归属，不含任何具体服务状态。处理顺序按“先本地后远端”排列，与故障概率无关。

订阅方案的失效里，只有令牌和停服两项完全由运营方控制。入口地址、证书与出口信誉需要运营方处理，但处理需要时间，免费额度的工单优先级又低。自备方案的失效里，除了供给方不存在，其余全部落在自己身上。这个差别决定了“找谁”这个问题在不同方案下的答案不同，也决定了免费方案在关键时刻的救援能力更弱。

## 隐私、日志与支持

### 谁能看到什么

| 观察方 | 自备方案 | 订阅方案 | 商业 VPN 免费档 | 能降低到什么程度 |
| --- | --- | --- | --- | --- |
| 服务器持有方 | 只有云厂商 | 运营方与其运维 | 厂商 | 取决于主体是否可追溯 |
| 链路观察者 | 见得到入口地址与时序 | 同左，另可见订阅域名 | 同左 | 加密内容，不隐藏连接事实 |
| 客户端软件 | 开源可审查 | 取决于所选客户端 | 厂商分发，通常闭源 | 官方渠道下载并校验 |
| 账号与支付体系 | 通常不涉及 | 常要求邮箱或手机号 | 常要求注册 | 独立邮箱，最小化信息 |

自备方案里，服务器由你控制，日志开不开由你决定。订阅方案里，运营方持有服务器，连接时间、源地址、目标域名与流量体积在技术上都可以被记录。条款写“不记录日志”时需要看它具体指哪一层，连接元数据与内容日志是两件事，能承诺前者不记录已经算克制。

### 日志的三种深度

连接元数据包括时间、源地址、目标域名与流量体积，多数服务在运维层面必然接触。DNS 查询记录能看到你解析了哪些域名。内容日志需要终止 TLS，正规服务不会这么做，恶意客户端可以，方式是替换证书或安装根证书。判断风险时先问哪一种，再问保留多久。

### 支持渠道的实际差别

自备没有客服，只有自己的日志与搜索引擎。订阅方案的免费额度通常有工单或群组入口，排队时间不承诺，回答质量取决于值班的人。商业 VPN 的免费档有客服入口，优先级排在付费用户之后。三种情况在故障时刻的差别，比在正常时刻大得多。

### 退出成本

自备要销毁服务器、快照与备份，避免旧 IP 被别人接手后带着你的配置。订阅方案要删订阅、注销账号、撤销支付授权，并清理客户端里保存的规则集与日志。商业 VPN 要卸载应用并确认订阅已取消。退出成本在进入时最低，在依赖形成后最高，这两件事通常同时发生。

## 免费、试用与低价的边界

三个词在日常使用里被混着说，落在成本与承诺上分得很开。下表按四个维度拆开，帮助判断手上这一条属于哪一档。

| 档位 | 现金支出 | 期限 | 额度承诺 | 判断要点 |
| --- | --- | --- | --- | --- |
| 免费 | 零，或仅注册 | 无承诺，可随时终止 | 通常不写，或写得含糊 | 谁在承担服务器成本 |
| 试用 | 零，可能需绑卡 | 有明确起止 | 一次性额度或限时 | 到期后是否自动转付费 |
| 低价 | 有明确对价 | 按周期续费 | 写在条款里 | 单位成本与退出条件 |
| 公益 | 零，可能接受捐赠 | 无承诺 | 无 | 是否有维护者与公告渠道 |

边界模糊的情形有三种。赠送额度在活动结束后继续存在，但额度缩水，形式上仍是免费。限时活动在结束后转为低价档，用户以为自己在用免费，实际已经进入付费流程。免费档与付费档共用服务器，免费用户被限速，条款里只写“尽力提供”。

判断时问五个问题。领取过程是否出现支付授权。额度与期限是否写在同一页。到期后会不会自动扣费。条款是否允许随时变更且不通知。出口是否与其他用户共享。五个问题里有两个答不上来，就按最坏情况估算，不要按宣传页估算。

## 新手应先确认的五件事

### 第一件，缺的是哪一层

先判断手上有没有软件、有没有节点、有没有可用的服务器。三样都缺的人，第一步应当去官方仓库下载客户端，而不是先找订阅。已经有客户端的人，问题通常在服务器与线路上。这一步判断错，后面的搜索都会跑偏。

### 第二件，服务器成本由谁承担

找到供给方，看它靠什么活。靠获客预算的，活动结束就停。靠广告的，免费档会随转化率调整。靠捐赠的，维护者离开就断。靠你自己的，账单在，服务就在。这一项决定的是寿命，不是速度。

### 第三件，额度四要素是否写在同一页

量、期、设备、速率四项要在同一处能找到。分散在三篇文章里的说明，等于没有说明。缺项时按最保守的取值估算，例如把“不限流量”当成每天 1 GB，把“3 台设备”当成 1 台。

### 第四件，失效时的切换路径

在开始使用之前写下三件事。备用线路是什么，放在哪里。什么条件触发切换，例如连续 6 小时不可用。切换后旧配置保留多久。免费方案的平均寿命以周计，没有切换路径的人会在故障当天花掉几个小时。

### 第五件，要交出的信息与权限

邮箱、手机号、支付方式、设备权限、证书校验，五项里每一项都要问必要性。能用独立邮箱就不用主邮箱，能关自动续费就关掉，能不装根证书就不装。要求关闭证书校验才能连接的服务，直接停止使用。

| 确认项 | 通过标准 | 证据形式 | 不通过怎么办 |
| --- | --- | --- | --- |
| 缺失层级 | 能说清缺软件还是缺服务器 | 一句话写下来 | 回到官方仓库或预算判断 |
| 成本承担者 | 能找到出钱的一方 | 官方页面与条款 | 按短期线索处理 |
| 额度四要素 | 四项写在同一页 | 页面快照 | 按最保守值估算 |
| 切换路径 | 备用线路已就位 | 本地配置文件 | 先准备备用再启用 |
| 信息与权限 | 五项都能说明必要性 | 权限清单 | 拒绝授权或放弃 |

## 安全与合规边界

免费方案的风险集中在三处。软件来源，安装包是否来自官方仓库，签名与哈希能否核对。服务主体，运营方是否可追溯，条款是否写明日志范围。权限授予，客户端要求的虚拟网卡、无障碍、通知读取是否每一项都有必要。三处里任何一处说不清，就不适合放账号与支付类流量。

代理改变的是出口地址，加密的是设备到入口这一段。它没有改变你正在使用代理这一事实，也没有改变浏览器指纹、登录状态与支付信息。任何声称绝对匿名的免费方案都不值得信任，日志可以记录，时间相关性可以分析，账号行为可以把多次访问连起来。

证书校验不能关闭。客户端提示证书错误时，核对域名、有效期与签发者，或者停止使用。关闭校验等于允许链路上的任何一方替换证书并读取明文。不同司法辖区对代理工具与跨境访问的规定不同，使用前自行确认当地法律、服务条款与可接受使用政策。

## 常见问题

### 客户端开源，为什么还要关心服务器是谁的

开源只覆盖软件这一层。代码公开意味着转发逻辑能被审查，安装包能被复现，它说明不了服务器在谁手里、日志留多久、出口会不会被替换。开源内核配上来路不明的订阅，流量照样经过别人的机器。判断顺序是先看订阅来源，再看条款，最后才看客户端版本。把软件可信与服务可信分开，是这篇文章最想留下的一条区分。

### 免费机场与自建哪个更适合长期使用

看你能承担哪一种成本。自建要付服务器与域名费用，还要自己处理证书、封禁与升级，时间投入稳定但不一定低。免费机场把运维转移给运营方，代价是额度、期限与可用性都不承诺。长期使用的话，可控性比省钱重要，愿意维护的人选自建，不愿意的人选有条款约束的低价套餐。免费档在两边的账上都算不出优势。

### 机场写“不限流量”，限制在哪里

限制通常落在速率、并发与公平使用条款三处。速率被压到几百 Kbps 时，流量确实不限，能做的事却很有限。并发按出口 IP 计算，同一时间多设备登录会触发限速或断开。公平使用条款允许运营方对高占用用户单独处理，措辞一般很宽。看到不限流量先找这三项，找不到就按每天 1 GB 估算，再判断是否符合需求。

### 试用额度和免费额度在成本上有什么区别

试用有起算点与结束时间，成本记在运营方的获客预算里，到期后要么停，要么转成付费。免费额度通常没有明确期限，随时可以调整或取消，成本由同一条预算或广告收入承担。两者在现金上都是零，在确定性上差很多。试用适合做一次有边界的验收，免费额度适合当备用。把试用当长期方案，会在到期那天遇到麻烦。

### 同一条订阅在不同客户端里节点数量不一样，为什么

服务端会按 User-Agent 返回不同格式，Clash YAML、sing-box JSON 与 Base64 列表的节点表达方式不同，字段不兼容的节点会被客户端跳过。内核版本也会影响解析，旧内核不认识新字段，遇到就整条丢弃。还有一种情况是订阅开启过滤，按地区或协议只返回一部分。排查时对比原始响应内容与客户端日志，不要先怀疑令牌。

### 订阅链接能不能分享给朋友

技术上可以，实际不建议。订阅地址里的令牌等同于账号凭证，拿到的人能拉配置、消耗额度、看到出口，部分服务还能看到设备记录。分享之后额度按人头分摊，限速更容易触发，运营方也可能因为多 IP 登录判定为共享。需要给朋友用时，让他自己注册，把链接当作密码管理，不截图、不放进公开仓库。

### 免费方案要装虚拟网卡或网络扩展，安全吗

这项权限本身是功能必需的，TUN 模式要通过虚拟网卡接管路由，移动端的 VPN 权限要接管全部应用的流量。风险不在权限，在谁拿到它。官方仓库发布、有签名与哈希、更新记录连续的项目，与第三方打包站的安装包拿到同样的权限，可信度差很远。授予之前核对来源，授予之后定期看更新日志有没有新增权限。

### 面板流量和系统统计对不上，怎么核对

先统一单位，100 GB 约等于 93.1 GiB，套餐写 GB 而系统显示 GiB 时差 7%。再确认是否上下行合计，本地统计通常只有下行。最后算倍率，用一次可复现的下载做基准，记录本地字节数与面板变化量，两者相除就是实际倍率。三项都核对完还有明显差额，再去看是否有后台更新或规则流量被计入。

### 预算每月 10 元，选机场还是自建

按前面的假设表算，自建月成本 120 元，10 元档订阅的单位成本约 0.109 元每 GB，自建要到月用量 1,100 GB 才追平，而那条假设里的流量上限只有 500 GB。这个预算下选订阅更合理。自建的价值在可控性与固定出口，不在单价。把预算、用量与时间价值写下来，答案通常自己会浮出来。

### 什么时候应该停止使用免费方案

四个信号。它开始承载账号、支付或工作交付。每月排障超过一小时。你需要固定出口或稳定上传。你无法确认服务器与运营方是谁。出现任意两个，就把关键流量迁走，免费方案退回备用。迁移时保留旧配置两周，确认新方案在高峰时段也能用，再删除订阅与令牌。继续用的理由如果只剩“还没出事”，那不算评估。
